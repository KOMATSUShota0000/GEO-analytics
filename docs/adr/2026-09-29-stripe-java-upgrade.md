# ADR-082: Stripe のライブラリを上げ、支払い完了のお知らせを読めるようにする

## 日付
2026-09-29

## 状況

PLAN-1（#167）の実機確認で、テスト用カードで支払うと `stripe listen` に `checkout.session.completed` と `customer.subscription.updated` が流れ、アプリも `[200]` を返したのに、プランが切り替わらなかった。

- Stripe からのお知らせ（Webhook のイベント）は、Stripe アカウントの既定の API の版で届く。オーナーのサンドボックスは `2026-05-27.dahlia`
- アプリの stripe-java 28.4.0 は `2025-02-24.acacia` 向け。stripe-java は、イベントの版の系統（日付の後ろの `acacia`・`dahlia` などの名前）が自分と違うと、`getDataObjectDeserializer().getObject()` で中身を返さない
- `StripeWebhookService` は中身が無ければ警告をログに出して何もせずに戻り、`StripeWebhookController` は `200` を返す。Stripe は届いたものとみなして送り直さないので、支払いは済んだのにプランが変わらないまま残る
- お知らせを受け取る側のテストが無く、これまで見つからなかった（ADR-022 の残課題「実鍵（テストモード）での E2E 検証」も未実施だった）

## 決定

**stripe-java を 28.4.0 から 33.4.2（`dahlia` 系。2026-09 時点の最新の安定版）に上げる。** あわせて、オーナーの Stripe が送る版で組み立てたお知らせでプランが切り替わることを確かめるテスト（`StripeWebhookServiceTest`）を足す。（オーナー確定 2026-09-29、#167）

## 理由

### 読み方をゆるめず、版をそろえる

版が違っても中身を読ませる `deserializeUnsafe()` を使う案もあった。アプリが読む項目（`metadata` の `workspaceId`・`plan`、顧客ID、契約ID、先頭の料金ID）は新しい版のお知らせにも同じ形で入っていたので、動きはする。ただしそれは「書式が違うかもしれないが読む」ことで、今後の版で項目が変わっても気づけない。ライブラリを上げれば、版の違いはライブラリが吸収する。

上げる作業は `pom.xml` の1行だけだった。28.4.0 から 33.4.2 までの互換性のない変更のうち、アプリに関係するのは次の2つで、どちらも動きは変わらない。

- 30.0.0: `RateLimitException` の親クラスが `InvalidRequestException` から `ApiException` に変わった。`StripeCheckoutService.classify` の振り分け（一時的な問題）は変わらない
- 32.0.0: お知らせの読み取り方法を取り違えるとエラーにするようになった。これは v2 の軽量イベント向けで、アプリは v1 のイベントを `Webhook.constructEvent` で読んでいる

### 33.4.2 を選ぶ

stripe-java は系統名（`dahlia`）だけを比べるので、`dahlia` 系（32.0.0 以降）のどれでも `2026-05-27.dahlia` のお知らせを読める。Stripe は同じ系統の中では互換性を壊さない方針なので、最新の安定版にした（`-beta` は使わない）。

## 影響

- `pom.xml`: `stripe.version` を 33.4.2 にした
- 決済ページを作るときに Stripe へ伝える版も `2026-08-26.dahlia` になる。上げた後に実機で、決済ページが開くこと・「←」で `/pricing` に戻ること・テスト用カードで支払うとプランが切り替わることを確かめた（2026-09-29）
- `StripeCheckoutService` のコメントから「`RateLimitException` は `InvalidRequestException` の子クラス」の1文を消した（オーナー確認済み）。判定のコードは変えていない。ADR-078 の同じ説明も直した
- 新規: `StripeWebhookServiceTest`（支払い完了・契約の変更・解約・別の鍵で署名されたお知らせ）。28.4.0 のままでは、支払い完了・契約の変更・解約の3件が「プランの切り替えが呼ばれない」で落ちることを確かめた
- **本番で Stripe にお知らせの送り先（Webhook エンドポイント）を登録するときは、API の版を `dahlia` 系にする。** 送り先は版を指定して登録でき、指定しなければアカウントの既定の版になる。系統が違うと、今回と同じく支払ってもプランが切り替わらない
- **Stripe が `dahlia` の次の系統を出し、アカウントや送り先の版をそれに上げるときは、stripe-java も同じ系統に上げる**

## 対象外

- 中身を読めなかったお知らせにも `200` を返している点（Stripe が送り直さない）。版がそろえば起きないため、今回は変えない
- 決済を終えて戻ってきた画面（`/?billing=success`）での完了表示（#166 の対象外）
