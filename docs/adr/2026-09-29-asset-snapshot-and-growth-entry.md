# ADR-084: 資産スナップショットを保存できるようにし、「成長の推移」への入口を付ける

## 日付
2026-09-29

## 状況

解析が終わるたびに、プロジェクトの GEO Readiness とローカルトラストの件数を1行ずつ記録する「資産スナップショット」（`geo_asset_snapshots`、ADR-027）がある。戦略ダッシュボード（`/projects/{id}/strategy`）の2つのグラフは、この記録から推移を描く。調べると次の問題があった（#180）。

- **スナップショットが一度も保存されていなかった。** 開発用 DB では、完了した解析が6件あるのに記録は0件だった。`GeoAssetSnapshotPipeline` は、合図を受けると新しい仮想スレッドの中でワークスペースを `WorkspaceRepository.findById` で直接読んでいた。新しい仮想スレッドには呼び出し元のテナント文脈が引き継がれず、`@Transactional` も通らないので、RLS 用の組織IDが接続に渡らない。ワークスペースが見えず、「workspace missing」で何もせずに終わっていた（#174 のお知らせと同じ落とし穴）
- **戦略ダッシュボードには、どの画面からもリンクがなかった。** そのため、グラフが空でも気づかれなかった
- ダッシュボードには、仮置きの文「🔒 基礎スコアが上位プランで開示されます（プレースホルダ）。」、内部のプロジェクトID、「ホーム」だけの戻る導線が残り、背景もほかの画面と違っていた
- 結果画面と印刷用レポートの「インサイトサマリー」（「スコア推移」）は、今見ている1回の解析のデータだけを日付ごとに平均していた。1回の解析はふつう1日で終わるので点が1つしかなく、推移になっていなかった。プロジェクト全体の推移を返す API（`GET /projects/{id}/analytics`）はあるが、画面からは呼ばれていない

## 決定

オーナー確定事項（2026-09-29）:

- 戦略ダッシュボードは**残して直し、入口を付ける**
- 入口の文言は **「成長の推移」**、置き場所は結果画面の「プロジェクト」欄（「プロジェクト設定」の隣）
- ダッシュボードの粗は**今回あわせて最低限直す**。上位プランへの誘導（Teaser）は仮置きの文ではなく改めて設計する（#192）
- インサイトサマリーは**結果画面と印刷用レポートから外す**。SoM の推移は、定期監査の作り直し（#177）で質問を固定してから「成長の推移」に足す。公開デモページは別セッションで扱うので触らない

実装:

- `GeoAssetSnapshotService.findWorkspace`（`@Transactional(readOnly = true)`）を足し、パイプラインはワークスペースを束縛してからこれを呼ぶ。仮想スレッドには `geo-asset-snapshot-job-{ジョブID}` の名前を付ける
- 結果画面の「プロジェクト」欄に「成長の推移」のリンクを足す（`returnJob` を渡し、ダッシュボードから結果画面へ戻れるようにする）
- ダッシュボード: 仮置きの文とその部品（`LockedInsightCallout`、ほかで未使用）を消す。プロジェクトIDの代わりに、見出しの下にプロジェクト名と対象 URL を出す（設定 API の `project_name`・`target_url` を使う。印刷した提案書にも出る）。戻る導線を「解析結果に戻る」（`returnJob` がないときは「ホームに戻る」）にし、背景をほかの画面と同じ薄藤色にする（印刷時は白）
- 結果画面と印刷用レポートから `AnalysisCharts` を外し、使われなくなった `resolveChartTrendData`・`aggregateTrendFromResultDetails` と日付の補助関数を消す。`AnalysisCharts` と `TrendData` は公開デモで使うので残す

## 理由

### インサイトサマリーを外す

点が1つのグラフが「スコア推移」と名乗っていて、利用者を誤解させていた。入口を足すと「スコア推移」と「成長の推移」が並び、さらに紛らわしくなる。本来の形（プロジェクト全体の SoM の推移）に戻しても、解析ごとに質問が作り直されるため、平均の上下が成果なのか質問の違いなのか区別できない（例: 社名を含む質問が増えるだけで平均が上がる）。正しく出せるのは、#177 で質問を固定してからになる。

### プロジェクト名を設定 API から取る

ダッシュボードの既存の API（`asset-snapshots`）はグラフの点だけを返す。名前と URL のためだけに新しい API を作らず、NOTIFY-2（ADR-080）で設定 API に足した `project_name`・`target_url` を使う。名前が取れなくてもグラフは見られるので、失敗したときは見出しの下を空けたままにする。

## 結果

- 解析が終わるたびにスナップショットが1行保存され、「成長の推移」のグラフに点が増えていく。`GeoAssetSnapshotPipelineIntegrationTest` で、直す前は保存されず、直した後は保存されることを確かめた
- 結果画面から「成長の推移」へ進み、戻れるようになった
- 画面の実機確認はマージ後にオーナーが行う（開発用 DB を共有しているため）
- 残課題: 上位プランへの誘導の設計（#192）、SoM の推移と使われていない `/analytics` API の扱い（#177）
