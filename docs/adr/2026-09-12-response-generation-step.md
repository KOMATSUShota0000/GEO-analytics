# ADR-044: 回答文（response）の確定を検証プロンプトの最初の手順にする

## 日付
2026-09-12

## 状況

検証プロンプト（`ConsultantPrompts.systemText`）に、`response` に何を書くかの指示が**存在しなかった**。スコアの入力はすべて `response` から導かれるのに、本文を書くかどうかがモデル任せだった。

| 計測 | STANDARD のプロンプト | PRO のプロンプト |
|---|---|---|
| #51 の A/B（各10回） | 5/10 | 0/10 |
| #58 の変更前再計測（一般検索・指名検索 各5回） | 3/10 | 0/10 |

PRO は末尾に競合指示が1文足されるだけで 0/10 まで落ちる。さらに `response` が空でも競合比較だけは埋められており、**回答文に出てこない競合名が15件中15件、評価対象（freee）自身が競合欄に入ったものが5件**あった。

ADR-039 の決定2（AI Overview が出なかったクエリは LLM 生成の回答で補完する）は、生成が安定していることが前提になる。安定しないまま材料を切り替える（#92）と、推定クエリの SoM が静かに0になる。

## 決定

### 1. 回答文の確定を、役割文の直後に「Step 1」として置く

| 材料 | `response` に入れるもの |
|---|---|
| あり（実測 AI Overview） | 渡された AI 回答の本文をそのまま（要約・翻訳・編集しない） |
| なし（推定） | 生成 AI 検索が返すであろう現実的な回答文（自然な日本語、150〜400字程度、実在のブランド・サービス名を含める） |

### 2. 他の項目はすべて Step 1 の `response` から導く

導入文、`extracted_brand_mention`、PRO の `competitorComparison` の根拠を `response` に揃える。競合は `response` に名前が出たブランドからのみ導く。

### 3. `response` は平文に限る（HTML タグ・マークダウン・URL を入れない）

### 4. 生成と評価を2回の呼び出しに分けることはしない

オーナー確定の順序（#58）は「まず指示を明示し、安定しなければ分ける」。明示で全条件が安定したため、分けない。

## 理由

### 先頭に置く理由

A/B で、後ろに1文足されただけで生成が崩れた。指示が末尾に積み増されても崩れないよう、手順の順序で守らせる。順序はテスト（`ConsultantPromptsTest.systemText_responseStepPrecedesEveryOtherInstruction`）で固定した。

### 平文に限る理由

改善タスクの説明文に向けた HTML の指示が回答文へ漏れ、実測30回中2回で `<a href='https://www.freee.co.jp/'>` のようなリンクが混入した。`response` は Java の言及計数（#59 のエンジン、#60 で接続）の材料で、URL の中のブランド名まで数えてしまう。

### 生成時に評価対象のブランド名を伏せない理由

評価対象を知った LLM が推定の回答文へ自社を差し込めば、推定クエリだけ SoM が水増しされる。伏せるには生成と評価を別の呼び出しに分ける必要がある。そこで**実在しない架空のブランド名**で一般検索を投げて確かめたところ、回答文に差し込まれたのは 2回の計測で合わせて**20回中0回**だった。差し込みは起きていないため、呼び出しを増やしてまで伏せる必要はない。

## 原価と待ち時間

モデル料金は gemini-2.5-flash の入力 $0.30／100万トークン、出力 $2.50／100万トークン（内部思考も出力として課金）。ADR-039 と同じく 150円/ドルで換算した。変更前は各条件3回、変更後は各条件5回で、架空ブランドの条件は除く。

| | 入力 | 出力 | 内部思考 | 1回あたり | 応答時間（中央値） |
|---|---|---|---|---|---|
| PRO 変更前 | 822 | 570 | 1,476 | ¥0.81 | 10.3秒 |
| PRO 変更後 | 970 | 616 | 1,567 | ¥0.86 | 11.6秒 |
| STANDARD 変更前 | 788 | 542 | 1,407 | ¥0.77 | 11.5秒 |
| STANDARD 変更後 | 926 | 533 | 1,433 | ¥0.78 | 10.9秒 |

**増分は1回あたり ¥0.01〜0.06** で、指示文が約150トークン長くなった分。内部思考の量と応答時間はほぼ変わらない。変更前も回答文が空のまま同じだけ課金されており、同じ原価で使えない結果を買っていた。

途中の計測で1回あたり約47秒かかったことがあるが、同じプロンプトの再計測で約11秒に戻ったため、Gemini 側の混雑による揺れと判断した。

### ADR-039 の原価表への追記

ADR-039 の原価表は SerpAPI のみで、LLM の費用を含めていなかった。検証の LLM 呼び出しを足すと次のとおりになる。**黒字上限が下がるのは今回の変更によるものではなく、もともと掛かっていた費用を表に足したため。**クエリ生成・ルーブリック監査・改善タスク生成など、検証以外の LLM 呼び出しはまだ含んでいない。

| プラン | SerpAPI | 検証 LLM | 解析1回 | 月あたり黒字上限（売上の14%以内） |
|---|---|---|---|---|
| Standard | ¥6.0 | ¥2.3 | ¥8.3 | **164解析**（SerpAPI のみでは 228） |
| Pro | ¥16.5 | ¥8.6 | ¥25.1 | **166解析**（SerpAPI のみでは 252） |
| Expert | ¥46.5 | ¥25.9 | ¥72.4 | **115解析**（SerpAPI のみでは 180） |

## 結果

- #92（材料を実測 AI Overview へ切り替える）の推定側が成立する。
- Step 1 の「写し」の分岐は、#92 で AI Overview をユーザー本文へ差し込むときに効く。差し込むテンプレートは「AI-generated answer」のブロックであることを明示すること。現行のサイト本文テンプレート（「Extracted website text follows」）は AI 回答ブロックではないため、#92 までのリアルタイム経路では生成側が働く。
- `ai_citation_position` と `token_count` の指示文は変えていない（#66 / #59 の範囲で、仕様変更はオーナー同意が要る）。
