# ADR-075: ログイン画面を「メールアドレス → 届いたコード」の2段階にする

## 日付
2026-09-26

## 状況

ログインをメールに届くコードに切り替える（#144）。API は発行（ADR-072）・照合（ADR-073）・送信回数の上限（ADR-074）がそろった。画面（`LoginPage`）はまだメールアドレスとパスワードの入力欄で、`POST /api/login` を呼んでいた。「開発環境の初期ユーザー: bootstrap@example.com / bootstrap」という表示も条件なしで出ており、本番のビルドでもそのまま出ていた（#148）。

オーナー確定事項（#144）のうち、本件に関わるもの:

- ログイン画面の表示は開発と本番で変えない。開発用の案内（Mailpit の場所など）は画面に出さず、手順書にだけ書く（確定事項6）
- 未登録のアドレスでも、画面は常に「コードを送りました」と出す（確定事項3）
- 失敗の理由を分けず、残り回数も出さない（確定事項11）
- 文言は、エンジニアでない代理店の担当者が説明なしで意味と次の行動を読み取れるものにする
- 画面の文言（2026-09-26 オーナー確定）

## 決定

**ログイン画面を2段階にし、パスワード欄と開発用の表示を消す。通信とエラーの読み取りは `auth/loginCode.ts` に分ける。**

| 段階 | 内容 |
|---|---|
| 1. メールアドレス | 「コードを送る」で `POST /api/auth/code`。202 なら2段階目へ |
| 2. コード | 入力したアドレスを大きく出し、6桁を入れて「ログイン」で `POST /api/auth/code/verify`。成功したら今までどおり元いたページへ戻る |
| 再送 | 「コードを再送する」は60秒押せず、残り秒数を出す。再送したら「前に届いたコードは使えなくなります」と出す |
| 戻る | 「メールアドレスを直す」で1段階目へ |

| うまくいかないとき | 文言 |
|---|---|
| コードが違う・期限切れ・使用済み（401） | 「コードが正しくないか、期限が切れています。うまくいかない場合は、コードを再送してやり直してください。」 |
| 60秒以内の再送（429 `login_code_resend_too_soon`） | 「続けて送ることはできません。あと◯秒待ってから、もう一度お試しください。」 |
| 回数の上限（429 `login_code_send_limit`） | 「送信回数の上限に達しました。◯分ほど待ってから、もう一度お試しください。」 |
| 通信エラー | 「通信エラーが発生しました。接続を確認して、もう一度お試しください。」 |

## 理由

### コードの入力を整える

日本語入力のままだと全角数字になり、メールから貼り付けると空白や前後の文字が交ざる。入力のたびに全角数字を半角に直し、数字以外を落として6桁で切る（`normalizeCode`）。API 側（`LoginCodeVerifyRequest`）でも全角数字を直すが、画面で直しておけば「6桁そろうまでログインを押せない」が正しく働く。

スマホで数字のキーボードが出るよう `inputMode="numeric"` を、メールからの自動入力候補が出るよう `autocomplete="one-time-code"` を付けた。

### 再送の待ち時間は画面でも数える

サーバーは60秒以内の再送を 429 で断る（ADR-074）。画面でも送った時刻から60秒ボタンを押せなくし、残り秒数を出す。押してから断られるより、いつ押せるかが先に分かる方が迷わない。サーバーから待ち時間が返ったとき（別のタブで送った直後など）は、その秒数で待ちを始め直す。

### 失敗の理由は分けない

API が理由を返さない（ADR-073）ので、画面も1つの文言にする。本人が「5回間違えてコードが無効になった」と気づけない点は、文言の後半「うまくいかない場合は、コードを再送してやり直してください」で補う。

### テナントのヘッダーを付けない

今までのログインは固定のワークスペースID（`X-Tenant-ID`）を付けて送っていた。コードの API はログイン前の経路としてテナントのヘッダーを要らない形にしてある（ADR-072）ので付けない。固定のワークスペースIDへの依存が1か所減る。

## 結果

- 開発用の初期ユーザーの表示が本番のビルドからも消えた。開発でのログイン方法は `docs/DEVELOPMENT_SETUP.md` の「動作確認」に書いた（Mailpit に届いたコードを入れる）。
- `POST /api/login`（パスワードでのログイン）は画面から呼ばれなくなった。サーバー側の撤去は AUTH-5（#149）で直後に行う。
- ログイン後の遷移（元いたページへ戻る）とリフレッシュ失敗時の案内（`?reason=`）は変えていない。
- フロントには自動テストの仕組みが無いため、`npm run build` と型チェックで確かめた。画面の見た目と実際の操作は、オーナーが開発サーバーを起動し直したときに確かめる。
