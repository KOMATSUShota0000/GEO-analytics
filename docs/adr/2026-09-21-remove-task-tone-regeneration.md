# ADR-068: 改善タスクのトーン再生成を撤去する

## 日付
2026-09-21

## 状況

解析結果の改善タスクカードに、トーン（プロ／フレンドリー／強調）を選んで本文をLLMで書き直す「再生成」機能があった（#134）。

2026-05-08 の「フェーズ2.4」（849812f）で追加されたもので、残っている記述はコミットメッセージの「Profit Guard（二重防壁）: Bucket4jによるレート制限とAOPクレジット予約を伴うトーン再生成機能」だけだった。これは守り方の説明で、ユーザーにとってなぜ必要かは書かれていない。ADR・計画メモ・Issue・PRにも、機能を作った理由の記録は無かった。ADR-061（改善タスクの根拠）と ADR-066（プラン基準のタスクゲート）は、既存機能として整合を取っただけである。

## 決定

**トーン再生成を API・サービス・画面ごと撤去する。**

`POST /api/v1/jobs/{jobId}/tasks/{taskId}/regenerate`、`TaskRegenerationService`、専用のレート制限・プロンプト・構造化出力・LLM Bean・例外、画面の `TaskToneToggle` と、そのための props の受け渡しを削除した。

## 理由

### 存在理由が無い

作った理由が残っておらず、プロダクトの核（4ペルソナ議論・ホワイトラベル出力・Teaser・利益率）のどれにも属さない。

### 解析結果を上書きし、元に戻せない

改善タスクの本文は、解析時に `AiRemediationService` がルーブリックのギャップを材料に生成し、`audit_histories.job_recommended_actions` に保存したものである（4ペルソナ議論の出力ではない）。再生成はこの本文を直接書き換え、履歴を残さないため、元の本文には戻せなかった。根拠（rationale / evidence）は元のまま保持されるため、言い換えた本文と根拠がずれる余地もあった。プロンプトは「事実は変えずに文体だけ変える」と指示していたが、それを検証する仕組みは無かった。

### 解析とは別にクレジットを消費する

再生成のたびに `@CreditReservation(amount = 10L)` でクレジットを消費していた。1解析＝1,000単位のスケールなので、1回あたり0.01チケットと少額である。撤去の主な理由ではないが、「1解析＝1チケット」とは別の消費経路だった。

### 検討した反論

代理店がクライアント向けに文体を調整する用途は考えられる。ただし記録が無く、本文は「内容をコピー」で持ち出して手元で調整できるため、上書きのリスクを負ってまで残す理由にはならないと判断した。

## 結果

- 改善タスクカードからトーン切替と再生成ボタンが消えた。本文は解析時に生成されたものだけになる。
- 再生成専用の LLM 呼び出し経路（Gemini 2.5 Flash）が消えた。
- DBスキーマの変更は無い。過去に再生成で書き換わった本文は、そのまま残る。
- ADR-061 の「文体の再生成で根拠を保持する」と、ADR-066 にある再生成ロックの記述は、対象が無くなった。
