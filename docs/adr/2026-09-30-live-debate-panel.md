# ADR-097: 結果画面の待ち表示を、4人のAIの議論を1発言ずつ見せる表示に置き換える

## 日付

2026-09-30

## 状況

解析結果の画面の待ち時間に、4人のAIの議論を1発言ずつ見せる（#194）。LIVE-4（#198、ADR-096）で、問い合わせの返事に議論の状態と発言が載るようになった。次は、それを画面に出す（#199）。

- 議論中の待ち表示は、決まった文言5つ（「ANALYSTが市場データを精査中...」など）が数秒ごとに切り替わるだけだった
- 見本の画面（オーナー確認済み、2026-09-29）の中央の画面「議論中」のとおりに作る

## 決定

### 1. 議論中の表示 `DebateLivePanel` を作り、待ち表示と置き換える

上から、見出しと説明、進み具合（ラウンド1 → ラウンド2 → まとめ）、4人の札、発言の並び。文言・配色・役割の説明は見本のとおり。

- **進行役の一言**（「測定結果と、改善タスク5件を読み込みました。…」）は AI の発言ではなく、画面が改善タスクの件数から作る。最初の発言が届く前（議論の準備中）は、この一言と、アナリストの札の「発言中…」が出る
- **誰への返事か**は、相手と立場から札の文言を作る（「イノベーターへの反論」「スケプティックの指摘を確認」「スケプティックへの応答」「条件つきで賛成」など）
- **根拠**は、測定結果なら「根拠：測定結果（質問ごとの言及）」と中身、改善タスクなら「根拠：改善タスク 2」と、そのタスクのタイトル・ラベル（効果・かかる時間）を出す。番号は画面の改善タスクの並びと同じ（#141）
- **「発言中…」の札**は、文字を流している発言者。届いた発言を流し終えたら、次に話す人（順番は固定なので、届いた件数から決まる）

決まった文言の待ち表示（`AI_ADVICE_LOADING_MESSAGES`）は消した。

### 2. 発言は1つずつ順に、文字を流して見せる

- 発言は数秒〜十数秒おきに届く。届いた発言は1つずつ順に流す。まとめて届いても飛ばさない
- 画面を開いた時点ですでに届いていた発言は流し直さず、いちばん新しい発言から流す
- 根拠の枠は、その発言を流し終えてから出す
- 動きを減らす設定（`prefers-reduced-motion`）の人には、文字を流さず一度に出す
- 読み上げソフトには、流している途中の文ではなく、発言の全文を渡す

### 3. 議論が終わっても、見ていた人には最後まで見せてから切り替える

議論が終わった知らせとディレクターの一言は、ほぼ同時に届く。すぐ結果に切り替えると、最後の発言を読めない。

- 議論を見ていた人には、最後の発言を流し終えてから、緑の帯「議論がまとまりました」と「結果を見る」のボタンを出す。押すと、総合診断・改善ロードマップ・少数意見に切り替わる（見本のとおり）
- 議論が終わったあとに開いた人には、最初から結果を出す
- 議論なし・失敗で終わったときは、見せる発言が無いので、議論の表示を閉じて結果を出す

### 4. 要約が空の発言は並べない

AI が形の崩れた応答を返すと、その発言の要約は空になる（ADR-094）。出す文が無いので、発言の並びには入れない。進み具合と「発言中…」は、空の発言も含めた届いた件数で決めるので、ずれない。

### 5. 印刷・スマホ

- PDF・印刷には出さない（`pdf-no-print`。印刷用は別の画面 `ReportPrintPage`）
- 4人の札は、狭い画面では2列、広い画面では4列に並べる

## 確かめたこと・確かめていないこと

- 部品を Node 上で描画して、文言と出し分け（根拠・返事の札・空の発言・動きを減らす設定・議論が終わったとき）を確かめた
- `npm run build` が通る。`npx tsc --noEmit` のエラーは既存の1件だけ
- **実際の画面での見た目と動きは、オーナーの確認待ち**。画面のテストを動かす仕組みが無く、ブラウザも使えないため

## 申し送り

- LIVE-6（#200）: 議論が終わったあとの1行（畳む・「議論の流れを見る」）を作る。開いたときは `DebateTranscript` に全部の発言を渡す。議論なし・失敗・古い解析の文言はオーナーに確認する
- DEMO（#188 の続き）: `DebateLivePanel` は発言の配列を渡せば動くので、見本のデータを流して公開デモに入れられる
