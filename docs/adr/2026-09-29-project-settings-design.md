# ADR-080: プロジェクト設定画面を結果画面と同じ見た目にし、届くメールの見本を添える

## 日付
2026-09-29

## 状況

プロジェクト設定画面（`/projects/{id}/settings`、`ProjectSettingsPage`）は、白い背景に MUI の枠が1つあるだけで、解析開始画面・結果画面の見た目（薄藤色のグラデーションの背景、白いカード、藍色のボタン）から浮いていた（2026-09-28 オーナー指摘「この画面だけ UI が質素すぎる」、#175）。どのプロジェクトの設定なのかも画面に出ていなかった。

NOTIFY-1（ADR-079、#174）で、お知らせはメールだけになり、宛先を3件まで登録できるようになった。受け取る側が「何が届くのか」を知る手段は、実際に解析を回すことしかなかった。

## 決定

デザイン案を2つ（案A: 1枚のカードにまとめる／案B: 項目ごとのカードと、届くメールの見本）キャンバスで見せ、オーナーが**案B**に決めた（2026-09-28）。

- 背景・余白・カード・見出しは結果画面（`JobAnalysisPage`）と同じ Tailwind の書き方にそろえる。MUI は保存完了のトースト（`Snackbar`）だけに使う（ログイン画面 ADR-077 と同じ扱い）
- 見出しの下に、プロジェクト名と対象 URL を出す。そのために設定 API の応答に `project_name`・`target_url` を足す
- 左に「解析完了のお知らせ」と「定期監査」のカード、右に「届くメールの見本」。スマホの幅では1列に並べる
- 宛先は1件ずつ行で出し、× で消す。件数（N / 3件）を出し、0件のときは案内文を出す。Slack のチャンネル用アドレス（`@….slack.com`）には吹き出しのアイコンを付ける
- 「Slackで受け取るには」は青い囲みに分け、Slack のヘルプ（日本語）へのリンクを添える
- 定期監査のトグルは今のまま残す（#173 のオーナー確定事項4）。見た目だけそろえ、スイッチは `role="switch"` のボタンにする
- 画面名は「プロジェクト設定」のまま（オーナー確定）。定期監査の作り直し（#177）で設定が増える見込みがあるため。結果画面の入口「定期監査・通知設定」とオンボーディングの「設定へ」も「プロジェクト設定」にそろえる

## 理由

### メールの見本を添える

宛先を登録する人が、何が届くかをその場で分かるようにするため。見本の数値と質問文は `[質問文1]` のように見本と分かる形にし、件名には実際のプロジェクト名を入れる。見本はメールの本文（`NotificationService.sendEmail`）の文言をそのまま写している。メールの文面を見直す #183 では、見本も合わせて直す（画面のコードにその旨のコメントを残した）。

### 保存ボタンを入力のカードのすぐ下に置く

デザイン案のスマホ幅では保存ボタンを見本の下（いちばん下）に置いていたが、入力のすぐ下に置いた。見本を読み飛ばして保存を押し忘れるのを防ぐため。

## 結果

- 設定画面の見た目が、解析開始画面・結果画面とそろった。どのプロジェクトの設定かが見出しの下で分かる
- 画面の実機確認はマージ後にオーナーが行う（開発用 DB を共有しているため）
- 残課題: メールの文面の見直し（#183）、定期監査の作り直し（#177）
