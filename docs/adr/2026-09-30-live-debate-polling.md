# ADR-096: 結果画面の問い合わせの返事に議論の状態と発言を載せ、議論が終わるまで問い合わせを続ける

## 日付

2026-09-30

## 状況

解析結果の画面の待ち時間に、4人のAIの議論を1発言ずつ見せる（#194）。LIVE-3（#197、ADR-095）で、発言と議論の状態が保存されるようになった。次は、それを画面へ届ける（#198）。

コードを読んで、今の画面の動きを確かめた。

- 結果画面は3秒ごとに `GET /api/v1/jobs/{id}` を問い合わせ、解析が完了すると止める（PDF の生成中だけは続ける）
- 議論は、解析の完了のあと裏で走る。総合診断・ロードマップ・少数意見は、議論が終わってから保存される
- 保存済みの総合診断が無いあいだ、この API は**テンプレートの診断文**で埋めて返す（#141 の決まり）
- そのため画面は、完了した直後にテンプレートの診断文を総合診断として出し、そこで問い合わせを止める。議論から作った総合診断・ロードマップ・少数意見は、**再読み込みするまで出ない**

#198 の引き継ぎでは「完了後も待ち表示が続くはず」と推測していたが、実際は「テンプレートの診断が出たまま止まる」だった。

## 決定

### 1. 返事に議論の状態と発言の一覧を足す

`JobStatusResponse` に2項目を足した。

| 項目 | 中身 |
|---|---|
| `debate_status` | `RUNNING`・`COMPLETED`・`SKIPPED`・`FAILED`。古い解析は null |
| `debate_utterances` | 発言の一覧（話した順）。`round`・`speaker`・`summary`・`reply_to`・`stance`・`evidence_kind`・`evidence_task_number`・`evidence_detail` |

- 発言は1解析で最大7件なので、毎回全件を返す
- 発言者・立場・根拠の種類は列挙の名前で返し、表示名は画面で決める（LIVE-5）
- 議論の状態は `JobEntity` に読むだけの列として足した。このエンティティは保存のたびに全列を書き戻すので、書ける列にすると、画面側の保存が裏の処理の書いた状態を古い値で上書きしうる

### 2. 発言の読み出しは別のサービスに分ける

`JobDebateQueryService`（`@Transactional(readOnly = true)`）をコントローラーから呼ぶ。発言は RLS（組織ID）で隔離していて、組織IDは別のクラスから呼ばれた `@Transactional` のメソッドでしか接続に渡らないため（R-02）。

### 3. 議論中のあいだ、画面は問い合わせを続ける

- 解析が完了していても、`debate_status` が `RUNNING` のあいだは問い合わせを続ける。それ以外（完了・議論なし・失敗・古い解析）は今までどおり止める
- 議論中は、テンプレートの診断文を総合診断として出さず、待ち表示にする。議論の結論だけを総合診断として出す
- 議論の終わりを検知したら、解析データ（`/analysis`）を取り直す。ロードマップと少数意見はそちらにあるため

これで、再読み込みしなくても議論の結論が出る。待ち表示を議論の表示に置き換えるのは LIVE-5（#199）。

### 4. 議論中のまま長く残ったものは、失敗として返す

サーバーが議論の途中で止まると（再起動など）、`RUNNING` の印が残り、画面が問い合わせを続けてしまう。ジョブの最後の更新（`jobs.updated_at`）から **15分** を過ぎた `RUNNING` は、`FAILED` として返し、発言も返さない（失敗した議論の発言は消す決まり、ADR-095）。

- 15分にした理由: 議論はふつう数分で終わる。AI の呼び出しが時間切れ（1回120〜180秒）とやり直しを重ねても収まる長さにした
- DB は書き換えない。読むたびに判定する。遅れていた議論があとで終われば、保存された結果がそのまま返る
- 判定はサーバー側に置いた。画面にはテストを動かす仕組みが無いので、「続ける・止める」の判断の中身は Java のテストで守り、画面は状態が `RUNNING` かどうかを見るだけにした

## 実機確認とトークンの実測

今回も見送った（2026-09-30 オーナー）。LIVE-5（#199）の画面の確認のときに、サイボウズで1回流して、ここまでの動きとトークン（ADR-085・094 で後回しにした分）をまとめて確かめる。

## 申し送り

- LIVE-5（#199）: `jobStatus.debateUtterances` と `jobStatus.debateStatus` を使って議論中の表示を作る。いまの待ち表示（`isDebateRunning` のとき）を置き換える。要約が空の発言の見せ方もここで決める
- LIVE-6（#200）: `SKIPPED`・`FAILED`・null（古い解析）の表示を決める
- 画面側のテストの仕組み（vitest など）は無い。入れるかどうかは別に決める
