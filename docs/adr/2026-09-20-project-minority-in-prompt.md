# ADR-065: プロジェクト単位の少数意見を解析プロンプトへ配線する

## 日付
2026-09-20

## 状況

`projects.minority_reports`（オンボーディング議論で得た「合意に至らなかった攻め手の候補」）が、**生成されて編集画面で見られるだけ**で、解析にもレポートにもプロンプトにも一切影響していなかった（#82）。

```
project.getMinorityReports() を読む場所
  → ProjectContextService（オンボーディング編集画面へ返すだけ）
  → 他になし
```

`.cursorrules` 10節「孤立したコードは許容しない」に照らすと、使うか撤去するかを決める必要があった。

## 決定（オーナー確定 2026-09-19）

**解析のプロンプト前置きに毎回載せる。撤去しない。**

解析ごとに生成されるマイノリティ・レポート（#80 / ADR-062）とは**別物として両立させる**。

| | プロジェクト単位（本件） | 解析単位（#80） |
|---|---|---|
| 出どころ | オンボーディング議論 | その回の解析の議論 |
| 性質 | 恒常的な「見立て」 | その回の測定結果に対する少数意見 |
| 役割 | 解析の**入力**（プロンプト前置き） | 解析の**出力**（画面・PDF に表示） |

### 刈り込み（プロンプト膨張の防止）

前置きは**クエリ1本ごとのプロンプトに毎回載る**。プロジェクト側の少数意見は1項目1,000文字まで許容され最大10件保存できる（`ProjectContextTextLimiter`）ため、そのまま載せると1解析で数万文字に膨らむ。

| 項目 | 上限 | 理由 |
|---|---|---|
| 件数 | 3件 | 上位から。10件すべては解析の焦点をぼかす |
| `insight` / `conflict_reason` | 各150文字 | 1クエリあたり約450文字に収める |
| `evidence` | **載せない** | 「オンボーディング入力のどこに拠り所があるか」であり、解析側の判断材料にならない |

`conflict_reason` は載せる。「この角度は検討されたが理由 X で見送られた」という情報が、解析側の議論の出発点として効くため。

### 組み立ての場所

前置きの材料をどこで集めるかを散らさないため、経路ごとに1箇所へ閉じる。

| 経路 | 入口 |
|---|---|
| リアルタイム | `JobPersistenceService.findJobPromptContext(jobId)`（JPA） |
| バッチ / ベンチマーク取得 | `BatchPersistenceService.findProjectMinorityReports(projectId)`（JDBC） |

## 影響

- マイグレーション不要（既存の `projects.minority_reports` を読むだけ）
- 追加の LLM 呼び出しは無い。入力トークンが1クエリあたり約450文字ぶん増える（限界利益率への影響は無視できる水準）
- `GeminiVerificationAdapter` はジョブを自前で引かなくなり、前置きの組み立てを `JobPersistenceService` に委ねる
