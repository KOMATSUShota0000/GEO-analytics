# ADR-047: 引用順位を Java で算出する（文中の登場順）

## 日付
2026-09-19

## 状況

SoM は「言及成分6割＋引用順位ボーナス4割」で構成される。引用順位（AI 回答の中で自社が何番目に挙げられたか）は LLM の自己申告で、**実測では全件 0** だった。つまり**スコアの4割が常に死んでいた**（#66）。

原因はプロンプトの定義にある。

> use 1 if the evaluated brand appears first among brands or named entities in an **explicit ranked or numbered preference list**; use 0 if there is no such list

実際の AI Overview は「クラウド会計ソフトでは freee やマネーフォワード、弥生会計が人気です」のような文章形式が多く、この定義ではすべて 0 になる。

## 決定

### 1. 回答文に登場する順番を引用順位とする（オーナー確定 2026-09-19）

番号付きリストでも文章でも同じ規則。先に名前が出たブランドほど上位とする。

### 2. 比較対象のブランド名は LLM、順序と位置は Java

回答文に実際に名前が出たブランドは LLM が挙げる（`competitorComparison`）。**どれが何番目かは Java が本文から決める**。`.cursorrules` 12節「確定的な物理量は AI に数えさせない」に従う。

### 3. 一致規則は #59 の言及計数と同じ

NFKC 正規化と小文字化で表記の揺れを吸収し、形態素の境界で始まり境界で終わる一致のみ採る（「ガスト」が「ガストロノミー」に誤一致しない）。読みでの一致は行わない。

### 4. 自社が登場しなければ 0

順位ボーナスも 0 になる。登場しないクエリを上位扱いしない。

### 5. リアルタイム経路とバッチ経路の両方を切り替える

LLM の申告値はスコアに使わず、比較のためログにだけ残す（`citation_position java=... llm=...`）。

## 理由

### 文中の登場順を採る理由

実際の AI 回答は文章形式が多い。先に名前が出るほど読者の目に入るため、「何番目に出たか」は可視性の指標として意味を持つ。明示リストに限る定義では、**測れる機会がほとんど無い**。

### 比較対象を LLM に挙げさせる理由

「回答文にどのブランド名が出ているか」を機械的に列挙するには、ブランド名の辞書が必要になる。辞書を持たない現状では、回答文を読んだ LLM に挙げさせるのが唯一の現実的な方法。挙げ損ねた場合は自社の順位が**低めに出る**（安全側）。

## 結果

- `citationBonus` が非ゼロを取りうるようになり、**SoM の値が上がる方向に変わる**。絶対値の再調整は #60 と併せて扱う。
- 比較対象が LLM の出力に依存するため、`competitorComparison` を返さない STANDARD プランでは、自社が登場すれば常に 1 位となる。プラン間でスコアを比べる際の注意点として #60 へ申し送る。
- 実測での確認は #60 の実データ確認時に、`citation_position java=... llm=...` のログで行う。
