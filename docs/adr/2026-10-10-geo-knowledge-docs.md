# ADR-102: GEO の知見を docs/geo-knowledge/ に、腐らせない書式で貯める

## 日付

2026-10-10

## 状況

クロールの方式（JavaScript で描かれるページへの対応など）を見直す前に、オーナーが「GEO では何が効くのか」の調べ直しを依頼した（#242）。AI がページを手に入れる経路、引用の選ばれ方、信頼の要因、日本市場、測り方を調べ、評価項目と照らし合わせた。

結果は会話の中にしかなかった。オーナーはこれをチームで共有し、GEO の知見として今後も貯めたいと考えた。読み手は、並行して開発する Claude のセッションで、人間向けの配慮は要らない（オーナー確定 2026-10-10）。

オーナーは同時に「ドキュメントは中身が腐った時点で価値がなくなる」と指示した。

## 決定

### 1. 置き場所はリポジトリの docs/geo-knowledge/（2026-10-10 オーナー確定）

共有ドキュメント（Claude Docs）とリポジトリの docs/ を比べて、docs/ にした。

- worktree にもそのまま入り、ファイルとして読める。コードや ADR と一緒に検索で見つかる
- 共有ドキュメントは、接続のないセッションからは読めず、リンクを知らないと見つからない
- 変更が PR に残り、コードと同じ時点の版がそろう

CLAUDE.md の「どこに何があるか」に入口を1行足し、どのセッションも見つけられるようにした。

### 2. 腐らせないための書式（私の判断で決めたこと）

オーナーの「腐らせない」という指示から、次の形にした。書式の中身は `docs/geo-knowledge/README.md` にある。

- 主張ごとに、根拠の種別（公式・査読・査読前・実測・調査会社・報道・個人）、出典の URL、出典の日付、確認した日を付ける
- 出典は主張の横に直接書き、番号で引く出典一覧は作らない。番号がずれると、どの主張の根拠かが分からなくなるため
- ファイルの先頭に `last_verified` と `review_by` を置く。変化の速い話題（クローラーの挙動、各社の方針）は3か月、研究の動向は6か月を目安にする。キーを英語にしたのは、あとで期限切れを機械的に見つけやすくするため
- コードを読めば分かること（配点、クラスの構成）は写さず、ファイルの場所を指す
- 一般的な知見と、このプロダクトへの当てはめ（`rubric-review-2026-10.md`）を分ける。当てはめは、どのコミットの時点かを書き、評価項目のコードを変えたら同じ PR で直す
- 腐りすぎたファイルは、勝手に消さず、削除してよいかオーナーに聞く

### 3. 業者の調査の扱い

GEO の調査の多くは、GEO・SEO のツールを売る業者によるもので、利益相反がある。使うときは `★` を付け、公式・査読の根拠が出たら差し替える。

## 確かめたこと・確かめていないこと

- 出典は 2026-10-10 に開いて確かめた。開けなかったもの（Bing Webmaster Guidelines の本文、Search Console のレポートの発表の本文、Semrush の本文）は、そう書いた
- AI のクローラーが JavaScript を実行するかは、一次の測定が2024年12月の1件しかない。都度取得のクローラーは不明のまま

## 結果

| 区分 | ファイル |
|---|---|
| 追加 | `docs/geo-knowledge/` の9ファイル（README・geo-model・crawlers-and-access・citation-selection・trust-signals・japan-market・measurement・open-questions・rubric-review-2026-10） |
| 変更 | `CLAUDE.md`（「どこに何があるか」に1行） |

本体のコードは変えていない。

## 申し送り

- 評価項目・クロール・計測を直す提案は `rubric-review-2026-10.md` にあるが、どれも未決定。直すときは別の issue にする
- 「ドキュメントを腐らせない」を、このフォルダだけでなくリポジトリ全体のルールにする件は #243 で扱う
- `review_by` の期限切れを CI などで知らせる仕組みは、まだない。必要なら別の issue にする
