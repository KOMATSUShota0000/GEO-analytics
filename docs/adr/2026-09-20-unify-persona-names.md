# ADR-060: ペルソナ名を1系統に統一する

## 日付
2026-09-20

## 状況

同じ「4人の議論」を名乗るペルソナの集合が2系統あった（#78）。

| 定義場所 | ペルソナ | 用途 |
|---|---|---|
| `domain/ai/DebatePersona` | ANALYST / SKEPTIC / INNOVATOR / DIRECTOR | オンボーディングと `DebateAdviceGeneratorService` の議論。**CLAUDE.md 記載のプロダクト核** |
| `ConsultantOutputSchema` | SEO_EXPERT / BRANDING / DATA_SCIENTIST / CONSULTANT | 検証の1コール内で `debate_log` を書かせるための enum |

後者は「1つのモデルに議論ログを書かせる」ためのもので、4人が議論するわけではなかった。しかも実測8件すべてで `debate_log` は**未返却**（任意フィールドのためモデルが常に省略）で、**一度も外に出ていなかった**。

## 決定

**後者（SEO_EXPERT 系）を撤去し、`DebatePersona` の4人に一本化する。**

検証プロンプトから `debate_log` / `roadmap_items` の任意フィールド指示を外し、スキーマ（構造化出力・バッチ設定の両方）と DTO からも削除した。

## 理由

### 1コールの自作自演を「議論」と呼ばない

#73 で本物の4ペルソナ議論（専用モデル・温度違い・チケット消費）を解析経路へ配線した。同じレポートに「1モデルが書いた議論ログ」の枠を残すと、**どちらが本物か実装依存**になる。

### ロードマップは議論の成果として出す

`roadmap_items` を検証の1コールに相乗りさせる設計は、実測で常に省略され機能していなかった。オーナー確定（2026-09-19）により、ロードマップは4ペルソナ議論のまとめ役（DIRECTOR）が出す（#77）。**出どころを議論側に一本化するため、検証側の枠を外す。**

## 結果

- ペルソナ名は ANALYST / SKEPTIC / INNOVATOR / DIRECTOR の1系統になった。
- 検証の構造化出力から2フィールドが消え、プロンプトが約350文字短くなった（入力トークンの節約にもなる）。
- 既存データへの影響はない（`debate_log` は一度も返ってきていない）。
- ロードマップの実装は #77 で、議論の成果として行う。
