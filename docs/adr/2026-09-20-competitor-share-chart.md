# ADR-064: 競合シェアを保存し、解析全体で1枚の円グラフとして出す

## 日付
2026-09-20

## 状況

CLAUDE.md がプロダクトの核の2番目に挙げる「SoM 円グラフ・**競合比較チャート**を画像/コンポーネント出力」のうち、競合側が出せていなかった（#112）。

| | 状態 |
|---|---|
| 競合名の抽出 | ✅ 実測で「回答文に無い競合」0件・「自社の混入」0件（#58 / #65） |
| 競合ごとの数値 | ✅ 回答文からの Java 実測（#64） |
| **保存** | ❌ `VerificationResponse.competitorResults` から先へ流れず捨てられていた（永続化は ADR-034 / V133 で撤去済み） |
| **表示** | ❌ 描画コードが無く、`--chart-competitor-1` という色変数だけが残っていた |

## 決定

### 1. 保存先は `audit_histories.competitor_results`（JSONB）。専用テーブルは復活させない

競合の永続化は ADR-034（2026-06-07 / V133）で**不可逆に撤去**されている。当時の理由は「書き込み専用・読み出しゼロの死蔵」で、正しい判断だった。今回はその前提が変わる — **読み出す側（競合シェア円グラフ）ができた**。

ただしテーブルを復活させる必要はない。

| 案 | 判断 |
|---|---|
| `job_competitor_scores` を作り直す | **却下**。RLS ポリシーを `audit_histories` への結合で書き直す必要があり、テナント境界の二重管理になる（#45 の教訓）。競合の行は監査1行に完全従属し、独立した検索も更新もしない |
| `audit_histories` に JSONB 列 | **採用**。テナント隔離は既存の行 RLS がそのまま効く。列1つで済む |

形は `[{competitorLabel, somScore, aiCitationPosition, mentionCount}]`。再解析のたびに**まるごと置き換える**（差分更新だと回答文から消えた競合が残り続ける）。

### 2. 競合の実測は1つの測定器に集約する（`CompetitorMeasurer`）

リアルタイム経路（`GeminiVerificationAdapter`）とバッチ経路（`GeminiResultProcessor`）が別々に測ると片方だけ直る事故が起きる。実際、バッチ経路は**競合を一切測っていなかった**（自社の指標だけ Java 実測にしていた）。選別（`CompetitorSelection`）＋言及計数＋引用順位＋SoM 算出を `domain/service/CompetitorMeasurer` に閉じ込め、両経路から呼ぶ。

### 3. 円グラフは解析全体で1枚、シェアの分母は SoM スコア比（オーナー確定 2026-09-20）

| 論点 | 決定 | 理由 |
|---|---|---|
| 粒度 | 解析全体で1枚 | 提案書に貼る図が1枚に確定する。クエリごとだと10クエリで10枚並ぶ |
| 分母 | 各社 SoM の合計に対する比 | 言及回数比では**上位で引用された価値（引用順位ボーナス）が消える** |
| 切片数 | 上位5社 ＋「その他」 | 細すぎる切片は読めない |

集計は `CompetitorShareAggregator`（純粋関数）に置く。画面と PDF が同じ数字を出す必要があるため、表示側には計算を持たせない（SSOT）。丸めは `StrictMath` で小数第1位（JEP 306、OS 差で数字を動かさない）。

### 4. ホワイトラベル

自社の切片は `--brand-color`、競合は彩度を落とした灰系の段階色。`self` フラグは**サーバが返す**（どの切片が自社かを表示側に判定させない）。

## 影響

- 新規マイグレーション `V142__audit_histories_competitor_results.sql`（既存ファイルは触らない）
- `CompetitorResult` を `application/dto` から `domain/model` へ移動（保存と集計がドメイン側で使うため）
- ADR-034 の「永続化しない」という決定を、**読み出す側ができたため**覆す。テーブルは復活させず列で持つ
- `JobAnalysisDetailResponse.competitor_shares` が増える（追加のみ）
- バッチ経路でも競合が測られるようになる（LLM 呼び出しは増えない。既存の回答文を Java で数えるだけ）
