# ADR-051: 感情強度を独立した「評判スコア」にする

## 日付
2026-09-19

## 状況

LLM が出す感情強度（-1.0〜1.0）が、どのスコアにも使われていなかった（#62）。`normalizedSentimentIntensity` という引数名で渡されながら正規化はされておらず、`weightedSom` の javadoc は「スコア本体には乗算しない」と明記。唯一の実用途は負感情アラートのフラグ（生値 < -0.5）だけだった。

`.cursorrules` 7節は「感情スコアのスケーリングには StrictMath を使用し」と定めるが、スケーリング自体が存在しなかった。

## 決定（オーナー確定 2026-09-19）

### 1. SoM にも権威軸にも混ぜない

- **SoM** は「どれだけ見えているか（可視性）」の指標。語られ方を掛けると、数字が低い原因が説明できなくなる
- **権威・エンティティ認知の軸** は「第三者にどれだけ言及されているか」の広がりを見る軸で、語られ方の良し悪しとは別物（オーナーが明確に否定）

### 2. 独立した「評判スコア」として持つ

0〜100 の指標として、クエリごとに **高／中／低**のバッジ、解析全体で**平均値**を示す。

### 3. 飽和型で変換する

`percent = 50 × (1 + tanh(1.5 × 生値))`。生値をそのまま百分率にしない理由は、LLM の生値が 0.85 と 0.90 のように誤差の範囲で揺れるため。両端を圧縮し、揺れが点差として出ないようにする。

- 生値 0.90 と 0.85 の差は **1点以内**
- 生値 0.70 と 0.40 の差は **8点以上**残る
- 生値 ±1.0 で飽和し、範囲外の値を渡しても 0〜100 を超えない

帯の境目は **75以上が「高」、45未満が「低」**（生値でおよそ 0.4 以上、-0.3 以下）。実測（AI Overview 20件）の生値は 0.0〜0.9 で、0.4 以上が「高」、0.1 前後が「中」になる。

### 4. 言及の無いクエリには評判を付けない

0点ではなく**値なし**とし、平均からも除く。言及されていないクエリに「どう言われたか」は存在しない。0点として混ぜると、可視性の低さが評判の低さとして二重に効いてしまう。

## 理由

### 生値の産出を LLM に任せる理由

Sudachi は形態素解析器で感情極性辞書を持たない。`.cursorrules` は「Sudachi（形態素／正規化のみ。感情・スタッフィングのルール補正には未使用）」と明記し、外部の感情辞書を入れることは「ライブラリ回帰禁止」に触れる。**生値の産出は LLM が正しく、Java が担うのはその後のスケーリングと集計**。

## 結果

- 評判スコアが API（クエリごとの `reputation_score` / `reputation_band`、解析全体の `reputation_average`）に出る。
- 画面と PDF のクエリ行に帯のバッジ、一覧の見出しに平均値を表示する。
- `SomScoreData.toRawMetrics` の引数名を `rawSentimentIntensity` に改め、名前と中身を一致させた。スケーリングは評判スコア側に閉じる。
- 負感情アラート（生値 < -0.5）は従来どおり生値で判定する。実測では該当なし。**否定的に語られるブランドを解析したときに、アラートと「低」バッジが揃って出ることを確認する。**
