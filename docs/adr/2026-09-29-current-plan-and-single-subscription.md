# ADR-087: 料金画面に「現在のプラン」を出し、支払い中の人の2つ目の申し込みを断る

## 日付
2026-09-29

## 状況

- 料金画面（`/pricing`）の3枚のカードはどれも「このプランで申し込む」で、どれが今のプランか分からなかった
- Stripe の決済ページは、申し込むたびに新しい契約を作る。支払い中の人がほかのプランを申し込むと契約が2つになり、二重に請求される。#181 の実機確認でも実際に2つできた
- 解約のお知らせ（`customer.subscription.deleted`）は、どの契約の解約かを見ずに Standard へ戻し、契約IDも残していた。契約の変更のお知らせ（`customer.subscription.updated`）は、どの契約のものでも「今の契約」を書き換えていた

## 決定

（オーナー確認 2026-09-29、#168）

- **料金画面は「契約中の人のプラン変更画面」とする。** B2B で無料プランは無く、支払っていない人は来ない前提
- **現在のプランは、ワークスペースのプラン（`subscription_plan`）で決める。** そのカードに「現在のプラン」の印を付け、ボタンも「現在のプラン」（押せない）にする
- **「Stripe で支払い中か」は、契約ID（`stripe_subscription_id`）があるかで決める。** 支払い中の人のほかのプランのボタンは「プラン変更はお問い合わせ」にし、画面下の問い合わせへ移動させる（PLAN-5 でフォームにつなぎ直す）
- **サーバーも、支払い中のワークスペースからの申し込みを断る**（409 `billing_already_subscribed`）
- **Stripe からのお知らせは、今の契約のものだけ反映する**
  - 解約: 今の契約なら Standard に戻し、契約IDを消す。ほかの契約なら記録だけしてプランを変えない
  - 変更: 今の契約のものか、まだ契約IDを記録していないとき（申し込み直後）だけ反映する。ほかの契約なら記録だけ
- 今のプランを読み込めなかったときは、今までどおり全カードを「このプランで申し込む」にする（支払い中ならサーバーが断る）

## 理由

### 現在のプランをプランの記録どおりに出す

画面に来る人は、前提からどれかのプランを支払っている。支払っていない `STANDARD`（新しいワークスペースの既定値と、解約した後）の人が来ると、Standard のカードが「現在のプラン」になって申し込めない。その人たちの扱いは #202 と新規登録を作るときに決める。

### 支払い中は契約IDの有無で決める

画面を開くたびに Stripe に問い合わせずに済み、Stripe が止まっていても判断できる。そのかわり、今の契約が解約されたら契約IDを消す。消さないと、解約した人がもう一度申し込めない。支払いが滞っている契約も「支払い中」のままで、Stripe が最終的に解約したときに消える。

### サーバーでも断る

画面を読み込めなかったとき、別のタブや開いたままの古い画面から押されたときも、二重に契約させないため。ただし、決済ページを2つ同時に開いて両方で支払った場合は防げない（申し込んだ時点ではまだ契約が無い）。これは #172 で扱う。

### 今の契約以外のお知らせは記録だけにする

契約が2つあると、古いほうの更新のお知らせで「今の契約」が古いほうに書き換わり、その後の解約の判定が逆になる。記録（`processed_stripe_events`）はするので、同じお知らせが送り直されても二度は処理しない。古い契約の請求はこれでは止まらない。新しい契約ができたら古い契約を自動で解約することは、オーナーの意向として、返金の扱いと一緒に #172 で扱う。

## 影響

- `GET /api/v1/workspaces/{id}` の応答に `has_stripe_subscription` を足した（`WorkspacePlanResolver.hasStripeSubscription`）
- `POST /api/v1/billing/checkout`: 支払い中なら 409 `billing_already_subscribed`（`CheckoutUnavailableException.Kind.ALREADY_SUBSCRIBED`）。設定の確認や Stripe の呼び出しより先に判定する
- `StripeSubscriptionSyncService`: `applySubscriptionUpdate`・`applySubscriptionDeleted` を足した。支払い完了（`checkout.session.completed`）が使う `applyPlanChange` は変えていない
- 画面: 共有のカード部品 `PlanComparison` が今のプランを受け取れるようにした（公開の `/plans` は渡さないので見た目は変わらない）。`PricingPage` はボタンを出し分け、開発用のプラン切り替えの後にカードも更新する
- 開発用のプラン切り替え（`PATCH /api/v1/workspaces/{id}/subscription`）はプランだけを変え、契約IDは変えない。切り替えると「現在のプラン」はそのプランになるが、支払い中かどうかは変わらない
- テスト: `StripeSubscriptionRlsIntegrationTest`（RLS が効く接続で、署名付きのお知らせから DB の書き換えまでを通す）など

## 対象外

- 支払っていない人・解約した人の扱い（#202）
- 利用者が自分でプランを変更・解約すること、同時に支払ったときの二重契約と古い契約の自動解約（#172）
- 問い合わせをフォームで受けること（PLAN-4・5、#170・#171）
