# ADR-073: ログインコードを照合し、入れなかった理由を区別せずに返す

## 日付
2026-09-26

## 状況

メールに届いたコードでログインする（#144）。ADR-072 でコードの発行（`POST /api/auth/code`）を作った。本件ではそのコードを照合してログインさせる（#151）。

オーナー確定事項（#144）のうち、本件に関わるもの:

- 10分で期限切れ、5回間違えたらそのコードは無効（確定事項4）
- 登録されていないアドレスでも、失敗の応答は登録済みと同じ（確定事項3）
- 失敗の理由を分けず、残り回数も出さない（確定事項11）
- 自動テストでもメールは Mailpit で受け取る（確定事項15）

## 決定

**`POST /api/auth/code/verify`（メールアドレス＋コード）を追加する。合っていれば今の `/api/login` と同じくアクセストークンとリフレッシュクッキーを返し、入れなければ理由を区別せず `401` を返す。**

| | 内容 |
|---|---|
| 成功 | `200`＋`{"accessToken": ...}`＋リフレッシュクッキー。コードは使用済みになる |
| 失敗 | `401`＋`{"error_code":"login_code_rejected","message":"コードが正しくないか、期限が切れています。"}`。誤り・期限切れ・使用済み・5回の超過・古いコード・未登録のアドレスで**すべて同じ** |
| 形式の誤り | `400`（6桁の数字でない、アドレスの形式が違う） |
| 入力の揺れ | 前後の空白を落とし、全角数字（０〜９）を半角にしてから確かめる。アドレスは大文字・小文字を区別しない |
| 判定 | 行を `SELECT ... FOR UPDATE` で押さえ、「未使用・期限内・失敗4回以下・ハッシュ一致」なら使用済みにし、それ以外は失敗回数を1つ増やす |
| トークン発行 | パスワードでのログインと同じ処理を `AuthService#issueTokens` に切り出して共通に使う |

## 理由

### 失敗の理由を区別しない

「残り2回」「期限切れです」のように理由や回数を返すと、それを出せるのはコードがある（＝登録済みの）アドレスだけなので、登録の有無が外から分かる（確定事項11）。本人が「5回間違えてコードが無効になった」と気づけない点は、画面の文言で「うまくいかない場合は新しいコードを送ってやり直してください」と補う（AUTH-4）。

### 未登録のアドレスでも同じ照合を行う

未登録のときだけ照合を省くと、行の検索・更新の分だけ応答が速くなり、応答時間で登録の有無が分かる。未登録のアドレスでは、架空のユーザーIDと組織IDを作って同じ照合（ハッシュ計算、行の検索、失敗回数の更新）を行う。架空の組織IDでは RLS によって行は見えず、更新も0行で終わる。

### 行を押さえてから判定する

同じコードを同時に2回送られたとき、判定と更新を別々に行うと2回とも成功しうる。失敗回数も、並行して送られると上限を超えて試せる。`FOR UPDATE` で行を押さえ、判定と更新を1トランザクションで行う。結合テストで、同じコードを同時に2回送っても成功が1回だけであることを確かめた。

### ハッシュは一定時間で比べる

`String#equals` は先頭から比べて違った所で抜けるので、一致した文字数で所要時間が変わる。`MessageDigest#isEqual` で比べる。

### 全角数字も受け付ける

日本語入力のままコードを打つと全角数字になる。画面（AUTH-4）でも半角に直すが、API を直接呼ばれても同じ扱いにするため、入力の段階で直す。

### トークン発行を共通化する

新しいセッションを作ってトークンを出す処理は、パスワードでのログインと同じ。重複させず `AuthService#issueTokens` に切り出した。パスワードでのログインは AUTH-5（#149）で撤去し、この共通部分だけが残る。

## 結果

- 失敗回数は、使用済みでない行に対してだけ増える。5回を超えても増え続けるが、判定は「5未満か」なので結果は変わらない。
- 未登録のアドレスの照合でも、架空の組織IDで RLS の文脈が設定され、`login_codes` に対して検索と更新が1回ずつ走る。
- 照合の経路 `/api/auth/code/verify` を、ログイン前の経路として4か所（認可の許可リスト・CSRF の除外・テナントヘッダーの除外・全体のレート制限の除外）に足した。総当たりの上限は、1コード5回（本件）と送信回数の上限（AUTH-3 #147）で決まる。
- 成功時には、今のパスワードログインと同じく、同じユーザーの他の端末のログインが切れる（1台制限。#144 確定事項9で今回は触らない）。
