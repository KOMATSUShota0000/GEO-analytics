# ADR-071: メールを実際に送れるようにし、送信先の設定が無ければ起動を止める

## 日付
2026-09-26

## 状況

ログインを「メールアドレス＋パスワード」から「メールに届く6桁のコード」に切り替える（#144）。その土台として、アプリから実際にメールを送れる必要がある（#145）。

調べると、メールを送る仕組みは一度も動いていなかった。

- `spring.mail` の設定がどの `application*.yml` にも無く、`JavaMailSender` が作られていなかった
- 既存の監査完了通知（`NotificationService`）は `JavaMailSender` が無いと**黙って送信を飛ばす**作りで、設定漏れに誰も気づけなかった
- 開発用の初期ユーザーは `DataSeeder` に `bootstrap@example.com` で固定され、作成もワークスペースが0件のとき（初回起動）だけだった。既存の開発DBでは、アドレスを変えても反映されない

## 決定

**送信先を環境変数で指定できるようにし、開発は既定で Mailpit へ、本番は既定値なしで送る。送信先が無ければ起動を止める。**（オーナー確定 2026-09-26、#144 確定事項6〜8）

| | 開発（`application-dev.yml`） | 本番（`application-prod.yml`） |
|---|---|---|
| 送信先の既定 | `localhost:1025`（Mailpit） | なし |
| 切り替え | `.env` に `MAIL_HOST` / `MAIL_PORT` / `MAIL_USERNAME` / `MAIL_PASSWORD` を書く（Gmail 等） | 同左（必須） |
| STARTTLS | 有効（必須にはしない） | 必須 |
| タイムアウト | 接続・読み取り・書き込みとも10秒 | 同左 |

- 開発用の受信箱 Mailpit を `scripts/mail.sh` で起動する（`axllent/mailpit:v1.31.2`、受信箱は `http://localhost:8025`）。
- `MailSettingsStartupCheck` が、`spring.mail.host` が空なら何が足りないかを示すメッセージで起動を止める。`app.mail.required`（既定 `true`）で切り替え、自動テストのプロファイル（`test` / `rls-it`）だけ `false` にした。
- 開発用の初期ユーザーのアドレスを `APP_BOOTSTRAP_EMAIL` で指定できるようにした（`app.bootstrap.email`、未指定なら `bootstrap@example.com`）。**起動のたびに、指定したアドレスのユーザーが無ければ作る。**
- 実際に Mailpit と Gmail に届くかは、コードを送る機能ができる AUTH-2a（#146）で確かめる（#144 確定事項16）。

## 理由

### 起動時に止める

メールはログインの唯一の入口になる。送信先の設定漏れは「誰もログインできない」に直結するのに、ログインしようとするまで気づけない。`GEMINI_API_KEY` / `JWT_SECRET` と同じく起動時に止める（確定事項8）。

検査は Bean の生成時（`InitializingBean`）に行う。既存の `SerpApiKeyStartupCheck` と同じ `ApplicationRunner` だと、Web サーバーが受付を始めた後に落ちるため。

設定の有無は「プロファイルが dev か prod か」ではなく `app.mail.required` で判定する。既定を `true` にしておけば、新しいプロファイルを作ったときに検査が黙って外れない。

### 開発は Mailpit を既定にする

Mailpit はメールを外に出さずに受け止めるので、架空のアドレス（`bootstrap@example.com`）でも受け取れ、実在の人にうっかり送る心配が無い。Gmail で実際に受け取りたいときは `.env` の書き換えだけで切り替わり、ログイン画面の表示は変わらない（確定事項6）。

本番の送信サービス（SES / SendGrid など）は選ばず、SMTP の設定だけ用意した（確定事項7）。選定と送信元ドメインの認証は公開準備で行う。

### タイムアウトを付ける

JavaMail の既定のタイムアウトは無限で、送信先が固まると送信スレッドが戻らない。ログインコードの送信を待つ利用者がいるので、10秒で打ち切る。

### 初期ユーザーのアドレスは開発プロファイルでだけ環境変数から読む

`.env` は spring-dotenv によって**自動テストにも読み込まれる**。`application.yml`（全プロファイル共通）で `APP_BOOTSTRAP_EMAIL` を読むと、`.env` に自分の Gmail を書いた途端、`bootstrap@example.com` でログインする結合テストが落ちる。環境変数は `application-dev.yml` でだけ読み、テストと本番は既定の `bootstrap@example.com` のままにした。

`.env` に `APP_BOOTSTRAP_EMAIL=` と空で書かれた場合は、空のアドレスのユーザーを作らないよう既定に戻す。

### 初期ユーザーの作成を別トランザクションにする

「無ければ作る」を毎回の起動で行うと、同じアドレスのユーザーが削除済みか別の組織にいる場合に、RLS で見えないまま一意制約（`uq_organization_users_email`）に当たる。クレジット補充と同じトランザクションだと起動ごと落ちるので、作成を分け、作れなければ警告を出して起動を続ける。

## 結果

- 開発で `MAIL_*` を書かなければ、送るメールはすべて Mailpit に届く。Gmail に切り替えると、監査完了通知（プロジェクト設定の「通知先メール」宛て）も実際に送られる。
- `.env` に `MAIL_HOST=` と空で書くと、開発でも起動しない（空文字は「設定あり」として既定値を上書きするため）。`.env.example` では `MAIL_*` をコメントにし、手順書のハマりどころにも書いた。
- `NotificationService` の「送る仕組みが無ければ黙って飛ばす」作りは残した。本件で送信先の設定が必須になり実害は消えたため（#145 の対象外）。
- 本番でも `DataSeeder` が動く問題（#152）は変わらない。初期ユーザーのアドレスは開発プロファイルでしか指定できないので、本番で別のアドレスの管理者ができることは無い。
- 手順は `docs/DEVELOPMENT_SETUP.md`（手順5・ハマりどころ）と `docs/DEPLOYMENT_ENV.md`（メール送信）に書いた。
