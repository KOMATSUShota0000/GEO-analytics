# ADR-078: Stripe の料金IDに既定値を持たせず、決済ページを開けない理由を画面で分ける

## 日付
2026-09-28

## 状況

料金画面（`/pricing`）の「このプランで申し込む」を押すと「決済ページの起動に失敗しました。時間をおいて再度お試しください。」と出て、Stripe の決済ページへ進めなかった（#167）。

原因は開発環境の設定と、設定の読み方の両方にあった。

- `.env` の `STRIPE_*` が `.env.example` の雛形のまま、すべて空だった。秘密鍵が無いので、決済ページの作成を Stripe に頼む時点で失敗していた
- **鍵を入れても失敗する状態だった。** `.env` に空で書かれた行は spring-dotenv が空文字として読み込むため、`application.yml` の `${STRIPE_SUCCESS_URL:既定値}` の既定値が使われず空になる（ADR-071 の `APP_BOOTSTRAP_EMAIL` と同じ問題）。料金ID（`STRIPE_PRICE_*`）と戻り先URL（`STRIPE_SUCCESS_URL` / `STRIPE_CANCEL_URL`）が空になっていた
- `application.yml` には料金IDの既定値（`price_1TeFu...`）があったが、どの Stripe アカウントで作られたものか分からなかった。料金IDはアカウントごとに違うので、作った人のアカウント以外では `No such price` で失敗する
- 失敗の理由にかかわらず、画面は「時間をおいて再度お試しください」と出していた。設定が足りないときは何度押しても通らない
- 決済ページで「← 戻る」を押すと、ログイン前の公開ページ（`/plans`）に戻っていた。申し込みはログイン後の料金画面からしか始まらないので、ログイン中の担当者が見込み客向けの宣伝ページに着いていた

## 決定

**料金IDに既定値を持たせない。空の `.env` の行で戻り先URLが消えないようにする。決済ページを開けない理由を「設定の問題」と「一時的な問題」に分け、画面の文言を変える。**（オーナー確定 2026-09-28、#167）

### 設定

- `application.yml` から料金IDの既定値を消した。ADR-022 の「価格IDは非機密のため既定値を持たせる」を覆す
- 戻り先URLは、`.env` に空で書かれていても既定値に戻す（`StripeProperties` のセッター）
- 決済ページで「← 戻る」を押したときの戻り先の既定を `/plans` から `/pricing` に変えた
- Stripe の設定が無くても、起動は止めない（`docs/DEVELOPMENT_SETUP.md` の「`STRIPE_*` は不要。決済フローが使えない」のまま）

### 決済ページを開けない理由の分け方

| 種類 | 当てはまるもの | 応答 | 画面の文言 |
|---|---|---|---|
| 設定の問題 | 秘密鍵・そのプランの料金IDが無い／Stripe が鍵や料金IDを断った（`AuthenticationException`・`PermissionException`・`InvalidRequestException`） | 503 `billing_not_configured` | 現在、オンラインでのお申し込みを受け付けられません。お手数ですが、画面下の「お問い合わせ」からご連絡ください。 |
| 一時的な問題 | Stripe につながらない・Stripe 側の障害・アクセスが多すぎる（`ApiConnectionException`・`ApiException`・`RateLimitException` など）／画面側の通信エラー | 502 `billing_temporarily_unavailable` | 決済ページを開けませんでした。少し時間をおいて、もう一度お試しください。 |

- **どの設定が足りないかは、サーバーのログにだけ出す**（値は出さない）。起動時に `Stripe の設定が足りません（STRIPE_SECRET_KEY, STRIPE_PRICE_PRO, …）`、押したときにも同じ名前を出す。`STRIPE_WEBHOOK_SECRET` が無ければ、支払ってもプランが切り替わらないことを起動時に警告する
- 画面には開発者向けの案内を出さない（AUTH のときの「開発用の案内を画面に出さない」と同じ考え方）

## 理由

### 料金IDに既定値を持たせない

料金IDは Stripe のアカウントごとに発行されるので、既定値が使えるのは作った人のアカウントだけになる。ほかの人には「料金が無い」という分かりにくい失敗を招くだけで、秘密鍵は必ず自分で入れる必要があるのだから、料金IDだけ既定値で済ませられる場面が無い。未設定なら、起動ログと押したときのログに `STRIPE_PRICE_PRO` のように足りない名前が出る。

### 画面の文言を2種類に分ける

設定の問題は、利用者が何度押しても通らない。「時間をおいて再度」と案内すると、利用者は待ってから押し直し、また失敗する。設定の問題のときは「お問い合わせ」へ誘導する。

Stripe に鍵や料金IDを断られた場合も、時間をおいても通らないので設定の問題に寄せた。`RateLimitException` は Stripe のライブラリで `InvalidRequestException` の子クラスとして作られているため、先に判定して一時的な問題に振り分ける。理由の分からない失敗（画面側の通信エラーなど）は、再試行で直る見込みがあるほうに寄せた。

### 戻り先を `/pricing` にする

アプリ内から `/plans` に着く道は、決済ページの「← 戻る」しか無かった（`/plans` と `/demo` は互いにリンクし合うだけで、どの画面からもリンクされていない）。元いた画面に戻すのが自然で、「← ジョブ解析に戻る」などの導線もそのまま使える。

## 影響

- 新規: `CheckoutUnavailableException`（種類 `NOT_CONFIGURED` / `TEMPORARY`）
- `StripeCheckoutService`: 足りない設定の確認と、Stripe の例外の振り分けを担う。`BillingCheckoutController` は Stripe の例外を受け止めなくなった（`GlobalExceptionHandler` が応答に変える）
- `StripeProperties`: 戻り先URLの既定値を持ち、空文字を既定値に戻す
- フロント: `createCheckoutSession` は URL か失敗の種類を返す。`PricingPage` は種類ごとに文言を出す
- `docs/DEVELOPMENT_SETUP.md` に Stripe の設定手順（手順6）を足した。`sudo` を使わない Stripe CLI の入れ方、WSL での `stripe login`、`stripe listen` で Webhook を受ける方法を含む
- **既存の開発環境の `.env` で `STRIPE_PRICE_*` を空のまま使っていた場合、これまでは他人の料金IDで失敗していたが、今後は「料金が設定されていない」ことがログで分かる**

## 対象外

- 今のプランのカードに「現在のプラン」と出すこと、支払い中の人の二重の申し込みを止めること（#168）
- 決済を終えて戻ってきた画面（`/?billing=success`）での完了表示（#166 の対象外）
- 公開ページ（`/demo`・`/plans`）への入口が無く、見込み客が申し込めないこと（新規登録を作るときに扱う）
