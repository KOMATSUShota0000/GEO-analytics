# ADR-077: ログイン画面を左右2分割にし、コードを6マスで入れる

## 日付
2026-09-27

## 状況

コードでのログイン（ADR-075）は動くようになったが、ログイン画面は MUI の初期設定のまま（ボタンが MUI 既定の青、白い画面に文字だけ）で、アプリ本体の見た目から浮いていた。製品名もロゴも出ておらず、利用者が最初に目にする画面として製品の魅力が伝わらなかった（#164）。

アプリ本体の見た目は次のとおり。

- 公開ページ（`PublicDemoPage` / `PublicPlansPage`）は Tailwind で、背景は薄い灰色（slate）、白いカード（角丸・薄い影）、ボタンと強調は藍色（`#4f46e5`、`--brand-color` の既定）
- 目立たせる所は、藍→紫→水色のグラデーション（`JobCreationPage` の作成中のボタン: 主色 → `#7c3aed` → `#0284c7`）

## 決定

オーナー確定事項（2026-09-27）:

| | 内容 |
|---|---|
| 形 | **左右2分割**。左半分に藍→紫→水色のグラデーションと製品の説明、右半分に入力欄。スマホの幅では左半分を出さず、入力欄の上に目印と製品名を出す |
| コードの入力 | **1マス1桁の6マス** |
| 製品名 | **GEO Analytics** |
| 目印 | ロゴの画像ができるまで、角丸の四角に「G」 |
| 左半分の文章 | 見出し「AI検索で、選ばれるサイトへ。」、説明、3つの強み、「Web制作会社・代理店のための AI検索診断」 |

- 見た目は公開ページと同じ Tailwind の部品（slate の文字、藍のボタン、角丸の入力欄）でそろえ、MUI のテーマ（`createTheme()` の初期設定）は使わない。リフレッシュ失敗時の案内（`?reason=`）のトーストだけは今までどおり MUI の `Snackbar` を使う。
- 入力欄の上に「① メールアドレス → ② コード」の手順を出す。
- ログインの流れ・API・文言（ADR-075）は変えていない。

## 理由

### 6マスでも自動入力と貼り付けを受け付ける

メールからの自動入力（`autocomplete="one-time-code"`）や貼り付けでは、1つのマスに6桁がまとめて入ってくる。1マス1文字に制限すると切り捨てられるため、入ってきた数字を正規化（全角→半角、数字以外を落とす）してから、そのマスから後ろへ振り分ける（`CodeInput`）。値は先頭から詰めた数字として持ち、途中のマスを押しても最初の空きマスへ移す。

### 次のマスへ移した直後の判定は最新の値で行う

プレビューで「5」「6」と続けて打つと、6が1マス目の5を上書きする不具合があった。1桁入れて次のマスへフォーカスを移した直後の `onFocus` では、props の `value` がまだ入力前の古い値のままで、「空きより後ろのマス」と判定されて1マス目へ引き戻されていた。最新の値を ref に先に書き、判定はそれを見るようにした（オーナーがプレビューで確認）。

### 左半分の目印は白地にする

グラデーションの上にグラデーションの四角を置くと溶け込んで見えなくなるため、左半分だけ白地に藍の「G」にした。スマホの幅（入力欄の上）では、グラデーションの四角に白の「G」。

## 結果

- ログイン画面は、パソコンの幅で左右2分割、スマホの幅で入力欄だけになる。
- `CodeInput` はログイン画面専用の部品として `components/auth/` に置いた。
- 製品名の表記は、ログイン画面が「GEO Analytics」、ブラウザのタブとアプリの既定のツール名が「Geo Analytics」、メールが「GEOアナリティクス」と、まだ3通りある。そろえるのは別の作業にする。
- フロントには自動テストの仕組みが無いため、`npm run build` と型チェックに加え、オーナーがプレビュー（別ポートで起動した画面）で見た目と6マスの操作を確かめた。
