# ADR-057: test-sync を本番のリアルタイム経路と揃える

## 日付
2026-09-20

## 状況

`test-sync` エンドポイント（1クエリだけ同期で処理して動作確認する口）が、**本番と違う材料で動いていた**（#68）。

| 経路 | 材料 |
|---|---|
| 本番のリアルタイム経路 | 実測の AI Overview（取れなければ推定）。ADR-045 |
| test-sync | 材料なし（ブランド名とクエリだけ） |

通るプロンプトが違うため、**test-sync で確認した挙動は本番の挙動を保証しない**。実測でも両者の出力は大きく異なっていた（競合が入る／入らない、`response` が空になる頻度）。

## 決定

**test-sync も「クエリごとに AI Overview を取得 → その本文を材料に検証」する。** 本番と同じ手順を踏み、材料の別（`MEASURED` / `ESTIMATED`）も同じ規則で記録する。

## 理由

動作確認用の口が本番と違う経路を通るなら、その口には意味がない。材料を揃えることが目的なので、取得も含めて同じ手順にする。SerpAPI の呼び出しが1回増えるが、**test-sync は1クエリだけを対象とする確認用の口**であり、本番の解析コストには影響しない。

## 結果

- test-sync の結果が本番と同じ材料・同じプロンプト・同じ版名（`V14_AIOVERVIEW`）で記録される。
- `material_source` が実測／推定を正しく示す（従来は常に `ESTIMATED` の固定記録だった）。
- これにより、**クロールした自社サイト本文を材料にする検証経路（`verifyWithUrl`）の呼び出し元が消えた**。撤去は後続の PR で行う（ADR-058）。
