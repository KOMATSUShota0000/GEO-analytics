# ADR-053: 競合の数値を Java 実測にし、選別を生成時に行う

## 日付
2026-09-19

## 状況

競合エンティティに渡している数値が**すべて捏造または自社からの流用**だった（#64）。

| フィールド | 実際に入っていた値 |
|---|---|
| `somScore` | LLM 自己申告の `share` × 100 |
| `aiCitationPosition` | **配列の添字 + 1**（LLM が返した順序であって引用順位ではない） |
| `visibilityStage` | **自社の値のコピー** |
| `matchStatus` | **`AUTO_MATCH` 固定** |
| `nounCount` | **0 ハードコード** |

6項目のうち実体があるのは名前だけだった。加えて名寄せエンジンには候補が渡っておらず、競合は全件 `OTHERS` へ潰れていた（#65）。自社が競合リストに混入し、「その他」という残余カテゴリも混ざっていた。

なお**名前そのものは #58 で正しくなっている**（回答文に登場したブランドのみ。実測で「回答文に無い競合」0件、「自社の混入」0件）。

## 決定（オーナー確定 2026-09-19）

### 1. 実測できる値だけを持つ

```java
public record CompetitorResult(
        String competitorLabel,      // 名寄せ後の表記
        Double somScore,             // 回答文中の言及から算出（自社と同じ式）
        Integer aiCitationPosition,  // 回答文での登場順（#66 と同じ規則）
        int mentionCount) {}         // 回答文中の言及回数
```

`visibilityStage`（自社のコピー）と `matchStatus`（固定値）は**フィールドごと撤去**した。`MatchStatus` enum も使い道が無くなったため削除。

### 2. 選別は生成時に行う

`CompetitorSelection.accept(llmが挙げた名前, 自社名, 名寄せエンジン)` が次を落とす。

- **自社**（名寄せで自社と同定されるもの）
- **残余カテゴリ**（「その他」「Others」など、実在しないエンティティ）
- **表記ゆれの重複**（先に採った表記へ寄せる）

### 3. 名寄せエンジンに候補を渡せるようにする

`EntityNormalizer.resolveAmong(名前, 候補群)` を追加した。既存の3段照合（正規化形の一致／読みの一致／バイグラム類似）はそのまま使う。未使用だった `isProPlan` 引数は撤去した。

## 理由

### 競合の SoM を自社と同じ式で出す理由

同じ回答文の中で「自社は52点、競合は47点」と並べられなければ比較にならない。別の式で出した数字を並べると、差がどこから来たのか説明できない。

### 選別を集約側ではなく生成時に行う理由

旧実装は集約側（`InformationTheoryBasedAggregator.aggregate()`）で `NO_MATCH` を除外していたが、生成側が `AUTO_MATCH` を固定で入れていたため**一度も発火しない死んだ防御**だった。判定できる場所（名前が手に入る生成時）で落とすほうが確実で、集約側は「与えられたものを集約する」に専念できる。

## 結果

- 競合の数値がすべて実測になった。**ただし現時点では保存も表示もされない**（`VerificationResponse` から先へ流れない）。保存・表示は #112 で行う。
- `aggregate()` は本番未配線のまま（#67 で扱う）。本 ADR では入出力の形だけ新しい `CompetitorResult` に合わせた。
- 選別ロジックを純粋関数として切り出したため、自社除外・残余カテゴリ除外・表記ゆれの重複除外をテストで固定できるようになった。
