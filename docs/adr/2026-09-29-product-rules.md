# ADR-088: ルールを棚卸しし、CLAUDE.md に番号付きで作り直す。.cursorrules は過去の記録にする

## 日付
2026-09-29

## 状況

ルールは `.cursorrules` と `CLAUDE.md` の2か所にあり、`CLAUDE.md` が冒頭の `@.cursorrules` で `.cursorrules` を読み込んでいた。AI（Claude）はその中身を「絶対に守るルール」として扱う。オーナーの見立てでは、そのうち半分ほどが今の実態や方針に合っていなかった（#178）。

- `.cursorrules` 10章の「従来のGEO可視性ランク（引用優先度）のデイリー計測…の新規実装を厳格に禁止」は、SEO を GEO に置き換えたときの名残で、GEO の中心機能である定期計測（#177）を禁じてしまっていた
- ルールにあるのに一度も実装されていないものがあった（Profit Guard、JFR でのピン留めの監視、クレディブル区間、デュアルLLM、OpenAPI 3.1、JNI の Semaphore、バッファプール）
- `synchronized` の禁止は、仮想スレッドのピン留めが理由だったが、Java 24（JEP 491）で解消している
- 利益率が `.cursorrules` では 86.4%、`CLAUDE.md` では 86% と食い違っていた
- コメント規約が2か所にあり、中身が少し違っていた
- この数日で「リポジトリを `@Transactional` なしで呼ぶと RLS で0件になる」落とし穴を2回踏んだ（#174・#180）が、ルールになかった

## 決定

ルールを1つずつコードの実態と照らし合わせ、オーナーと「残す／書き直す／消す／足す」を決めた（2026-09-29）。

- **残す（20件）**: ThreadLocal 禁止と ScopedValue、RLS による隔離、PostgreSQL・Flyway・JSONB、StructuredTaskScope と parallelStream 禁止、WebSocket 禁止と SSE、SSE の送り方、Idempotency-Key、StrictMath、数理の一元化、record と `@JsonProperty`、確定した数は Java で数える、SLF4J とスタックトレースの保存、命名、`SubscriptionIntegrationTest`、Bucket4j と Semaphore、詰め込みの減点、SSE で過程を見せる、false は0点、計画上の分母、名寄せの独自エンジン
- **書き直す**: デイリー計測の禁止 → SEO 由来の機能だけを禁止し、SoM の定期計測は対象外と明記／GUC の名前を実際の `app.current_org_id`・`app.current_tenant_id` に／利益率は **86%** に統一／ゼロアロケーションの対象を数理エンジンの重い処理に限定（バッファの使い回しもここに含める）／Idempotency-Key の対象を Gemini Batch への投入とジョブ作成の API に／「密度の高いコード」→「周りのコードに合わせる」／コメント規約は CLAUDE.md の版に一本化／CLAUDE.md の変わりやすい数字（ファイル数・テスト数）を書かない／仮想スレッドの命名は残し、名前のない分は #213 で直す
- **実装されていないもの**: Profit Guard は「コストを測り、売上の14%以内に収める」に書き直して残し、まず計測を #211 で入れる／JFR の監視・JNI の Semaphore は消す／クレディブル区間は消して #177 の「ぶれの扱い」に移す／デュアルLLMは外して「AI に渡す前に無害化する」に／OpenAPI 3.1 は外して「入力の境界は Bean Validation」に
- **緩める**: `synchronized` の禁止を解く。「ロックを持ったまま外部の呼び出しや時間のかかる処理をしない」は残す
- **足す**: DB は `@Transactional` のサービス（別のクラス）経由（R-02）／新しい仮想スレッドはテナントを束縛し直す（R-03）／DB に触る機能は RLS が効く接続でテストする（R-05）／画面やメールの文言は非エンジニア向け（R-31）／並行セッションでは worktree と番号の確認（R-33）
- 書き方: `CLAUDE.md` の中に「ルール」の章を作り、R-01〜R-33 の番号と、必要なものには「なぜ」を付ける（オーナー確定）
- **`.cursorrules` は消さずに過去の記録として残し、ルールとして参照・引用しない**（オーナー確定）。`CLAUDE.md` の `@.cursorrules` を外し、「触ってはいけない場所」の表にその扱いを書く

## 理由

- ルールが2か所にあると、どちらかだけが直されて食い違う。今のルールは1か所（`CLAUDE.md`）にする
- 古いルールが「絶対のルール」として読み込まれ続けると、必要な機能を禁止したり、AI が的外れな回り道をしたりする
- `.cursorrules` には当時の考えが残っているので、記録としては残す（オーナーの判断）。当時の意図を調べるために読むのはよいが、判断の根拠にはしない
- 番号を振ると、issue・ADR・PR から「R-02 に従って」のように指せる

## 結果

- AI は `CLAUDE.md` のルール（R-01〜R-33）だけに従う。`.cursorrules` は読み込まれない
- ソースコードのコメントには「`.cursorrules` 12節」のような引用が十数か所残っている。既存のコメントは AI が書き換えない決まり（コメント規約）なので、今回は触っていない。扱いはオーナーに確認する
- 関連: #211（AI のコストの計測）、#213（仮想スレッドの命名）、#177（SoM の定期計測・ぶれの扱い）
