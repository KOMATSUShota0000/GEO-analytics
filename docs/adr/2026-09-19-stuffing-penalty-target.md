# ADR-050: スタッフィング減衰は自社サイト本文にかけ、AI 回答にはかけない

## 日付
2026-09-19

## 状況

`.cursorrules` 7節は「ブランド言及密度が閾値（例3%）を超えた場合はパラボラ型減衰関数でスコアを減点する」と定めるが、配線されていなかった。`stuffingDensity` は sync / batch の両方で 0.0 のハードコードで、計算式では一度も参照されずログにだけ現れていた（#61）。

配線しようとしたところ、**#92 で前提が変わっていた**ことが分かった。測定の材料が自社サイト本文から **AI の回答文**に変わったため、同じ規則を SoM に適用すると「AI がたくさん言及してくれたこと」を罰することになる。

実測でも起きる。指名検索「freee freee.co.jp」の AI Overview は 121トークン中5回言及で**密度4.1%**。ブランド名で検索しているので当然の結果だが、3%閾値では減点対象になる。さらに ADR-049 で「密度5%で満点」と決めたため、4%が「ほぼ満点」と「減点対象」を同時に満たす矛盾が生じる。

## 決定

| 対象 | 扱い |
|---|---|
| **自社サイト本文**（ルーブリック監査がクロールしたもの） | **減点する。** 基礎スコアのコンテンツ軸（0〜50点）に残存係数を掛ける |
| AI 回答文（SoM の材料） | **減点しない。** `SomRawMetrics.stuffingDensity` は撤去した |

（オーナー確定 2026-09-19）

### 減衰の形

- 閾値 3%（`.cursorrules` の例示値）まで係数 1.0
- 3% を超えると放物線で単調減少し、**15% で係数 0**
- 放物線にするのは、閾値の直後はほとんど減らさず、離れるほど強く効かせるため。詰め込みは程度問題であり、閾値を1ポイント超えただけで大きく減点するのは実態に合わない

## 理由

### 自社サイトに適用する理由

キーワードスタッフィングは「自社が自分のサイトでやる行為」であり、罰する対象はそこにある。AI 回答での言及量は自社が直接操作できるものではなく、GEO の成果そのもの。

### 15% で 0 にする理由

閾値の5倍。通常の文章では到達しない水準で、到達するのは意図的な詰め込みか、極端に短いページに限られる。

## 結果

- 詰め込みのある自社サイトは基礎スコアのコンテンツ軸が下がる。SoM は影響を受けない。
- `SomRawMetrics` から `stuffingDensity` を撤去した（ゼロ固定のまま残すと孤立コードになる。`.cursorrules` 10節）。
- 実データ（freee のサイト）では密度が閾値を超えず、減点は発生しない見込み。**詰め込みのあるサイトを解析したときに、実際に減点されることを確認する。**
