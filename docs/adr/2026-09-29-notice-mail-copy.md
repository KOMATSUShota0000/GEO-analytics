# ADR-086: 解析完了のお知らせメールを非エンジニアにも分かる文面にし、結果画面へのリンクを入れる

## 日付
2026-09-29

## 状況

解析完了のお知らせメール（`NotificationService`、ADR-079）の文面に、次の問題があった（#183）。

- 件名と見出しが「監査完了」「GEO監査が完了しました」で、画面の呼び方（「解析」）と違っていた
- 「今回のSoM平均」「前回監査のSoM平均」「平均の増減」「変動TOP3」と、内部の言い回しがそのまま出ていた
- 2026-09-29 にオーナーの Gmail に届いた実例では、変動TOP3 の3件のうち2件が「今回 26.1」だけで、前回の値がなかった。解析のたびに質問を作り直すので、前回になかった質問が混ざり、動いたかどうかが言えない行が並んでいた
- メールから結果画面へ移る手段がなかった

## 決定

文面の案をオーナーに見せて決めた（2026-09-29）。

```
件名: [GEOアナリティクス] サイボウズ の解析が完了しました

サイボウズ の解析が完了しました。

■ AIの回答に取り上げられた割合（SoMスコア）の平均
今回 44.6（前回 38.9 から +5.7）

■ 前回から大きく動いた質問
1. サイボウズ cybozu.co.jp — 今回 63.9 / 前回 68.6 / Δ-4.8
※ 前回と同じ質問は1件でした。今回はじめて測った質問が2件あります。

▶ 解析結果を見る
https://（アプリのURL）/job/（解析のID）

このメールは、プロジェクト設定で登録された宛先にお送りしています。
```

- 「監査」を「解析」に、「SoM平均」を「AIの回答に取り上げられた割合（SoMスコア）の平均」にそろえる
- 質問の行は、オーナーの判断で**元の「今回 / 前回 / Δ」の形を残す**（「こちらのほうが分かりやすい」）
- **「前回から大きく動いた質問」には、前回と比べられる質問だけを並べる**（オーナー確定）。前回になかった質問は数だけ書き添える。前回の解析がないとき、前回と同じ質問が1つもないときは、その旨を書く
- **結果画面へのリンクを入れる**（オーナー確定）。アプリの URL の設定 `app.public-base-url`（環境変数 `APP_PUBLIC_BASE_URL`）を足す。開発では何もしなくても `http://localhost:5173`、本番では未設定ならリンクを出さない
- 設定画面の「届くメールの見本」（ADR-080）も同じ文面にそろえる

## 理由

### 比べられる質問だけを並べる

前回の値がない質問は、動いたかどうかが言えない。数だけ書き添えることで、「前回と比べられた質問が少ない」ことも読み手に伝わる。毎回同じ質問を測る仕組みは #177 で扱う。

### URL の設定は開発と本番の設定ファイルだけで読む

`.env` は自動テストにも読み込まれる（`application-dev.yml` の注記）。共通の `application.yml` で環境変数を読むと、開発者の `.env` によってテストの結果が変わるため、開発（`application-dev.yml`）と本番（`application-prod.yml`）でだけ読む。本番で既定値を持たせないのは、設定し忘れたときに `localhost` へのリンクを利用者へ送らないため。

### 件名と本文を組み立てる処理を分ける

文面はオーナーと決めたものなので、`NotificationService.subject`・`htmlBody` に分けて、`NotificationMailBodyTest` で文面そのものを確かめる（ログインコードのメール `LoginCodeMailer` と同じ形）。

## 結果

- お知らせメールが画面と同じ呼び方になり、比べられない質問が並ばなくなった。結果画面へ1クリックで移れる
- 本番では `APP_PUBLIC_BASE_URL` の設定が要る（`docs/DEPLOYMENT_ENV.md` に追記）
- 実機での確認（Gmail への到着とリンク）はマージ後にオーナーが行う
