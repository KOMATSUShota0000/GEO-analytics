# ADR-049: SoM の飽和設定を実測に合わせる

## 日付
2026-09-19

## 状況

ADR-048 で入力を Java 実測へ切り替え、`sourceWeight` を SoM から外した。その状態で実データ（実測 AI Overview 本文20件、ブランド freee）を測ったところ、飽和設定が実態とかけ離れていた。

| | 設定値（旧） | 実測 |
|---|---|---|
| 言及密度（言及回数 ÷ 形態素トークン数） | 30% で飽和 | **0.24%〜4.1%**（中央値 0.6%） |
| 言及回数 | 12回で飽和 | **0〜5回** |

その結果、言及成分の平均は 0.10 にとどまり、**スコアの大半が「1位に出たか」だけで決まっていた**（言及の多寡で動くのは6点程度）。

## 決定

**言及密度の飽和を 5%、言及回数の飽和を 5回とする**（オーナー確定 2026-09-19）。配分（言及6：順位4）は変更しない。

### 候補の比較（実測20件の平均 SoM）

| 密度飽和 | 回数飽和 | 1位のとき | 順位なし | 言及成分の平均 |
|---|---|---|---|---|
| 0.30 / 12（旧） | | 46.2 | 6.2 | 0.10 |
| **0.05 / 5（採用）** | | **58.9** | **18.9** | **0.32** |
| 0.03 / 4 | | 64.3 | 24.3 | 0.41 |
| 0.02 / 3 | | 71.0 | 31.0 | 0.52 |

個別のクエリで見ると次のようになる（どちらも1位に出た場合）。

| | 旧 30%/12回 | 採用 5%/5回 | 2%/3回 |
|---|---|---|---|
| 3回言及・307トークン | 48点 | **63点** | 83点 |
| 1回言及・412トークン | 43点 | **47点** | 53点 |
| 差 | 5点 | **16点** | 30点 |

## 理由

### 実測の最大値に合わせる理由

飽和は「これ以上は満点」の線であり、**実際に到達しうる上限**に置くのが自然。実測の最大は密度 4.1%・5回だったため、5% / 5回とした。

### さらに緩めなかった理由

2%/3回まで下げると、1回言及されただけでほぼ飽和する。改善の余地（言及を増やす動機）が数字に現れなくなり、提案の材料として弱くなる。

### 配分を触らなかった理由

引用順位は #66 で初めて実際に動くようになったばかりで、揺れ具合のデータが1解析分しかない。**配分を動かすなら、数解析ぶんの順位の揺れを見てから**判断する。

## 結果

- スコアが全体に上がる。平均 SoM は 46 → 59（1位のとき）、6 → 19（順位なしのとき）。
- 言及の多寡が16点程度の差として現れるようになり、「言及を増やす」提案がスコアに反映される。
- 実測の代表値（3回言及・307トークン・1位）で SoM が約63点になることをテストで固定した。設定を緩めすぎ・厳しくしすぎたときに気づける。
- 実データは freee 1ブランド分（20クエリ）。**業種やブランドを変えたときに分布が動く可能性があるため、他ブランドで解析したときに再確認する。**
