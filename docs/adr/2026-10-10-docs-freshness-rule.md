# ADR-103: ドキュメントを腐らせないことをルールにする（R-34）

## 日付

2026-10-10

## 状況

#242 で GEO の知見を `docs/geo-knowledge/` に置く方針を決めたとき（ADR-102）、オーナーが次のように指示した。

- ドキュメントは、中身が腐った時点で価値がなくなる
- これは今回の docs だけでなく、ほかのドキュメントにも当てはまる
- 腐りすぎて不要になったドキュメントがあれば、削除してよいか聞いてほしい。あえて過去の記録を残しているものはそのままでよい

この方針は、1台の PC にある Claude のメモにしか書かれていなかった。メモは、ほかの PC やクラウドのセッションからは見えない。

## 決定

CLAUDE.md のルールの章「作業の進め方」に R-34 を足す。ルールにすることは 2026-10-10 にオーナーが決めた。文言は #243 で示した案のままで、PR でオーナーが確かめる。

> **R-34** ドキュメントは、中身が腐らないように保つ。変わりやすい事実には確認日と出典を付け、コードを読めば分かることは写さずにファイルの場所を指す。関係するコードや事実を変えたら、同じ PR でドキュメントも直す。腐りすぎて役に立たなくなったドキュメントは、勝手に消さず、削除してよいかオーナーに聞く。あえて残している過去の記録（既存の ADR、`.cursorrules`）は対象外とする。

- 全セッションが読む CLAUDE.md に書き、メモに頼らないようにした
- 「作業の進め方」に置いたのは、特定の技術ではなく、どの作業にもかかる決まりだから（私の判断）
- 過去の記録の扱いは、「触ってはいけない場所」の表（既存 ADR・`.cursorrules`）と合わせた

## 結果

| 区分 | ファイル |
|---|---|
| 変更 | `CLAUDE.md`（ルールの章に R-34） |

## 申し送り

- 既存のドキュメント（README、`docs/` の手順書など）の棚卸しはしていない。必要なら別の issue にする
- 古い記述を機械的に見つける仕組みはまだない。`docs/geo-knowledge/` は先頭の `review_by` で期限を持つので、CI で検査する候補になる
