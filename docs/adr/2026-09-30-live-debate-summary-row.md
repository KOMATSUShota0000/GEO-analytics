# ADR-098: 議論が終わったあとは1行に畳み、「議論の流れを見る」で開けるようにする

## 日付

2026-09-30

## 状況

解析結果の画面の待ち時間に、4人のAIの議論を1発言ずつ見せる（#194）。LIVE-5（#199、ADR-097）で、議論中の表示ができた。残りは、議論が終わったあとの表示（#200）。

- 議論を見ていた人が「結果を見る」を押したあとと、議論が終わったあとに開いた人には、総合診断・改善ロードマップ・少数意見だけが出ていた。議論の中身を読み返す入口が無い
- 議論の発言を出せない解析がある: 議論を行わなかった（`SKIPPED`）、議論が途中で失敗した（`FAILED`。発言は消してある、ADR-095）、発言を保存するようになる前の古い解析（状態が null）

## 決定

### 1. 議論が終わった解析には、総合診断の上に畳んだ1行を出す（`DebateSummaryRow`）

見本の画面（オーナー確認済み、2026-09-29）の「議論が終わったとき」のとおり。

- 左に4人のアイコンを少し重ねて並べ、見出し「4人のAIの議論から、改善の進め方が決まりました」と、小さな説明「2ラウンド・発言7件・根拠にした測定結果と改善タスク 5か所」を出す
- 数は実際の発言から数える。進行役の一言は AI の発言ではないので数えない。要約が空の発言も数えない（画面に並べないため、ADR-097）。根拠が1つも無いときは、根拠の部分を出さない
- 右のボタン「議論の流れを見る」で、その下に発言の並び（LIVE-5 の `DebateTranscript`）を開く。開いたら「閉じる」になる。文字は流さず、全文を出す
- 総合診断・競合シェア・改善ロードマップ・マイノリティ・レポートは今のまま

### 2. 議論の発言を出せない解析の表示（2026-09-30 オーナー確定）

| 場合 | 表示 |
|---|---|
| 議論を行わなかった（`SKIPPED`） | 「この解析では、4人のAIの議論は行っていません。総合診断は測定結果から作成しています。」 |
| 議論が途中で失敗した（`FAILED`） | 「4人のAIの議論が途中で止まったため、議論なしで総合診断を作成しました。議論の分のチケットは消費していません。」 |
| 古い解析（状態が null） | 何も出さない（今までどおり） |

- 一言は、総合診断の上に灰色の小さな枠で出す（`DebateAbsenceNote`）
- 議論は全プランで走る前提なので、無かったときに何も言わないと、議論を経た結論と区別がつかない
- チケットについて書けるのは、失敗したときに全額返す決まり（2026-05-30）があるため。サーバーが止まって返金が走らなかった予約も、1時間ごとの掃除（`StaleReservationSweeper`）で返る
- 古い解析に何も出さないのは、本番の利用者がまだおらず、対象が開発中の解析だけのため

### 3. 印刷・スマホ

- PDF・印刷には出さない（`pdf-no-print`）
- 狭い画面では、見出しとボタンを縦に並べる

## 確かめたこと・確かめていないこと

- 部品を Node 上で描画して、件数の数え方と文言を確かめた
- `npm run build` が通る。`npx tsc --noEmit` のエラーは既存の1件だけ
- **実際の画面での見た目と動きは、オーナーの確認待ち**（LIVE-5 と同じ）
