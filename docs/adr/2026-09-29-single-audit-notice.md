# ADR-081: 「解析完了」の合図は解析が終わったときの1回だけにする

## 日付
2026-09-29

## 状況

Pro 以上のプランの解析では、「解析完了」の合図（`ProjectAuditCompletedEvent`）が2回出ていた（#176）。

1. 解析が終わったとき（`JobQuerySubmissionService` のリアルタイム経路、`AsyncBatchService` のバッチ経路）
2. その後、ギャップ分析の Gemini バッチが終わったとき（`AsyncBatchService.pollOneGapAnalysisJob`）

ギャップ分析は、他の質問と比べて自社の見え方が極端に良い／悪い質問について、AI が質問ごとの個別アドバイスを書くもの。Pro 以上だけで行い、極端な質問がないときはバッチに出さない（`GapAnalysisService.runForJob`）。

合図を受けているのは、お知らせのメール（`NotificationService`）、最終監査日時の更新（`ProjectLastAuditService`）、資産スナップショット（`GeoAssetSnapshotPipeline`）の3つ。いずれもギャップ分析の結果を使っていない。

- お知らせに載せるのは SoM の平均・前回との差・大きく動いた質問で、ギャップ分析では変わらない。2通目は1通目とまったく同じ中身だった
- スナップショットは V13 のスコアとローカルトラストの件数で、これもギャップ分析では変わらない

2回目の合図は、ギャップ分析の巡回と一緒にフェーズ4.5（`c0561e1`）で入っていたが、理由は残っていない。

## 決定

- **ギャップ分析のバッチが終わったときに「解析完了」の合図を出すのをやめる**（オーナー確定 2026-09-28）
- お知らせ・最終監査日時・スナップショットは、どれも解析が終わった直後の1回だけ動く

## 理由

- メールの中身はどちらの時点でも同じなので、早く届く「解析完了の直後」を選んだ。Gemini のバッチは終わるまで時間がかかることがある（Google の案内では最大24時間）
- 合図を2種類に分けて、お知らせだけを1回にする案もあった。しかし、残りの2つもギャップ分析の結果を使わないので、合図そのものを1回にするほうが単純で、同じ日のスナップショットが2行できることもなくなる

## 結果

- Pro 以上の解析でも、お知らせは1通だけ届く
- 最終監査日時は解析が終わった時刻になる（以前はギャップ分析が終わった時刻で上書きされていた）
- `AsyncBatchServiceGapPollingTest` で、ギャップ分析が終わっても合図を出さないことを確かめる。直す前のコードではこのテストが失敗することを確認した
- 資産スナップショットが保存されていない疑い（#180）は、別に扱う
