# GEO の知見（入口）

GEO（AI の回答で引用・推薦されること）で何が効くかを、根拠と出典つきで貯める場所。読み手は、このリポジトリで開発する Claude のセッション。人間向けの読みやすさは考えない。

評価項目・クロール・計測の設計を変える前に、関係するファイルを読むこと。

`rubric-review-*` 以外は一般的な知見で、このプロダクトのコードには依存しない。プロダクトへの当てはめは `rubric-review-*` にだけ書く。

## 書式

各ファイルの先頭に次を置く。

```
---
last_verified: YYYY-MM-DD   # ファイル全体を最後に確かめた日
review_by: YYYY-MM-DD       # この日を過ぎたら、使う前に確かめ直す
---
```

`rubric-review-*` だけは、`review_by` に日付ではなく見直しの条件を書き、`code_snapshot` に読んだコードのコミットを書く。

主張は1つずつ、次の形で書く。

```
- 主張（1〜2文。数字には単位と対象を付ける）
  - 根拠: [種別] 発行元「題名」 出典の日付 URL
  - 確認: YYYY-MM-DD
```

- 根拠が複数あれば `根拠:` を複数行にする。主張と根拠が食い違うときは、両方を書く
- 出典は主張の横に直接書く。番号で引く出典一覧は作らない（番号がずれて腐るため）
- 出典の日付が分からないときは「日付表示なし（YYYY-MM-DD 閲覧）」と書く
- 推測は「（推論）」と書き、根拠の行を付けない
- 分からないことは「不明」と書き、推測で埋めない

### 根拠の種別（上ほど強い）

| 種別 | 中身 |
|---|---|
| 公式 | AI 事業者・検索事業者・インフラ事業者・政府の文書や発表 |
| 査読 | 査読付きの会議・論文誌に載った研究 |
| 査読前 | arXiv などの査読前の論文 |
| 実測 | 大規模な測定。業者によるものは `★` を付ける（GEO・SEO・MEO・PR のツールや支援を売る業者は利益相反がある） |
| 調査会社 | アンケート調査など |
| 報道 | 報道機関の記事。公式発表の紹介なら、元の発表を探して公式で書く |
| 個人 | 個人の実験・ブログ |

## 腐らせないための決まり

ドキュメントは、中身が古くなった時点で価値がなくなる（オーナー指示 2026-10-10）。

- `review_by` を過ぎたファイルの主張は、使う前に出典を開き直して確かめる。確かめたら主張と `確認:` の日付を直し、ファイルの `last_verified` と `review_by` も進める
- 確かめて覆っていた主張は、書き換える。経緯が判断に要るときだけ「YYYY-MM-DD に〜から変わった」と1行残す
- コードを読めば分かること（配点、クラスの構成）は写さず、ファイルの場所を指す。`rubric-review-*` のように時点つきの評価で数字が要るときは、どのコミットの時点かを書く
- 評価項目・クロール・計測のコードを変えたら、同じ PR で `rubric-review-*` を直すか、古くなった旨を書く
- 腐りすぎて役に立たなくなったファイルは、勝手に消さず、削除してよいかオーナーに聞く

## 足すとき

- 新しい知見は、合うファイルに足す。合うファイルがなければ新しく作り、上の表に1行足す
- 調査をしたら、未解決の問いを `open-questions.md` に足し、解けたものは消して該当ファイルへ移す
- 業者の調査しかない主張は、公式・査読の根拠が出たら差し替える
